# VLN 0.12.94 — возврат в аккаунт, приглашения и коды входа

## Добавление аккаунта Android

Выбор «Добавить аккаунт» открывает отдельный режим входа. Текущий сеанс, выбранный аккаунт и связь с сообщениями сохраняются до успешного входа в другой аккаунт. Кнопка «Вернуться в аккаунт» доступна на экране номера, после ошибки SMS и во время ожидания сетевого запроса. Она сбрасывает локальную попытку и останавливает слушатель SMS; для уже известного challenge отправляется отмена на сервер. Поздний ответ запроса не переключает аккаунт. Уже принятую провайдером SMS отмена интерфейса не отзывает. На этапе кода стрелка назад возвращает к номеру, на этапе номера — в существующий аккаунт.

Если старый клиент уже оставил экран входа с потерянным выбором аккаунта, после обновления кнопка использует сохранённые авторизованные аккаунты. Выход из аккаунта по собственной команде по-прежнему завершает его сеанс. Ошибка SMS-провайдера не считается успешной отправкой и не скрывается.

## Приглашения в группы

Android обрабатывает HTTPS-ссылки своего сервера `/app?invite=…`, совместимый вариант `token=…`, а также `volna://invite/…`. Приглашение сохраняется до входа и завершения первоначальной настройки профиля, затем открывается диалог с уже заполненным кодом. Вступление выполняется только после подтверждения; само открытие ссылки участников не добавляет. Повторное открытие ссылки и обновление токена не должны автоматически повторять вступление.

При открытии приглашения в Android-браузере сначала показана страница с кнопкой «Открыть в Волне», установкой приложения и отдельным переходом к входу в браузере. QR-код не навязывается на том же телефоне. Android не обязан автоматически открывать HTTPS-ссылку в приложении без настройки поддерживаемых ссылок; явная кнопка использует зарегистрированную схему приложения. Другие серверы, неоднозначные параметры и некорректные коды не принимаются Android-клиентом. Истёкшее или отозванное приглашение всё равно отклоняет сервер.

## Тот же код на авторизованных устройствах

После успешной отправки SMS существующему пользователю тот же шестизначный код появляется в личном служебном чате **«Волна — коды входа»**. Его получают существующие Android-, Web- и Windows-сеансы этого аккаунта через обычную доставку сообщений; устройства без связи увидят актуальное сообщение при восстановлении связи. SMS сохраняется. При первой регистрации без авторизованных устройств служебная копия не создаётся. Ошибка SMS-провайдера не обходится этой функцией.

Служебный чат приватный и доступен только адресату, публиковать в нём и создавать приглашения обычный пользователь не может. Копия создаётся один раз для попытки входа, повтор того же запроса не дублирует сообщение. Административные SMS и подтверждение смены номера таким способом не пересылаются.

В таблице сообщений хранится нейтральный текст. Код хранится отдельно как AES-GCM ciphertext, ключ выводится из серверного auth-secret с отдельной меткой назначения. Это не E2EE и не защита от доступа владельца сервера к базе и ключам. Открытый код выдаётся только при чтении собственного служебного чата и доставке в его сеансы. Он не включается в ответ запроса SMS, технические журналы, обычную пересылку сообщения и стандартную административную гидратацию сообщений. После использования, отмены, блокировки попытки, замены или истечения пяти минут сервер больше не выдаёт открытый код; ciphertext очищается при обработке изменения или ближайшей фоновой очистке. Старое SMS, ранее показанное уведомление или офлайн-кэш устройства могут сохранять уже недействительный код. Предупреждение «никому не сообщайте код» включено в сообщение.

## Обновление одной вставкой

Из существующего каталога проекта с `.env`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.94 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.94-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Обновите сервер и Android до 0.12.94. Служебные сообщения используют существующие сообщения/уведомления и совместимы с предыдущими Web/Windows-клиентами. Исправление возврата и открытие приглашений требуют обновлённого APK. Подпись Android, `.env`, данные и существующие авторизованные сеансы сохраняются.

Проверки: 233 Node-теста, полный набор из 224 Android unit/UI тестов, затем 13 целевых Android-проверок после окончательной правки ссылок; 13 целевых серверных проверок авторизации/служебных кодов. Реальные HTTP/SSE-проверки охватывают одинаковый код в Android/Web/Windows, изоляцию чужого аккаунта, запрет записи/приглашения в служебный чат, защиту пересылки, шифрование и инвалидирование. Проверены интерфейс возврата при ошибке и незавершённом SMS-запросе, диалог приглашения и мобильная веб-страница. Production-сборки Web и Windows renderer прошли. Физические устройства, реальный SMS-провайдер и установщик Windows в этой среде не проверялись.
