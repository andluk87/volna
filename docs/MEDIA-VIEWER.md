# Просмотр медиа: реализация ТЗ

В 0.12.76 реализованы MVP и основная галерея из приложенного ТЗ. Просмотрщик привязан к чату, а не сообщению. Исходное ТЗ не публикуется вместе с исходниками.

| Требование | Реализация |
|---|---|
| Выбранный файл, альбомы, переход между сообщениями | Один mediaId `m<messageId>` на появление вложения в истории; пересланные копии не схлопываются по attachmentId |
| Фото и видео | Единый хронологический список; видео останавливается при смене файла и в фоне Android |
| Открытие старого файла | `around` возвращает до 40 элементов около опорного; `before`/`after` догружаются при приближении к границам |
| Подсчёт | Итог показывается только когда загружены оба конца; отдельного SQL COUNT всей истории на каждый свайп нет |
| Жесты | Свайп, двойное касание 1×/2×, pinch 1–4×, панорамирование, вниз для закрытия при 1×, скрытие панелей |
| Превью | Уже доступное превью показывается сразу; оригинал догружается отдельно. Размер декодирования Android ограничивается Coil/размером viewport |
| Предзагрузка | До двух фото до/после текущего; видео заранее целиком не скачиваются. Неактуальные запросы отменяются |
| Кеш | Web/Windows: LRU до 80 МиБ в рамках сессии, без общего HTTP-кеша. Android: до 100 МиБ на аккаунт на диске, оригиналы отдельно от кеша Coil |
| Ошибка сети | Доступные файлы остаются; кнопки повтора для списка и оригинала |
| Изменения | Удаление выбирает соседа, новые сообщения не сбрасывают текущий ID; отзыв доступа очищает открытый диапазон и кеш |
| Галерея | Все/Фото/Видео, группы месяцев, 3–4 колонки; сохранён отдельный раздел файлов |
| Действия | Сохранить, переслать, поделиться, показать в чате, информация, удалить с подтверждением; сохранены ответ, рисование копии и личный стикер |
| Позиция переписки | Viewer отдельным слоем; обычное закрытие не вызывает загрузку/прокрутку переписки |

## API

`GET /api/chats/{id}/media?type=photo_video&direction=around&anchorMediaId=m85&limit=40`

Типы: `photo`, `video`, `photo_video`; направления: `around`, `before`, `after`. Следующий запрос передаёт `cursor` из `beforeCursor` или `afterCursor` с тем же `type`. Курсор непрозрачный, подписан HMAC, ограничен пользователем, чатом, типом, направлением и временем. После рестарта сервера устаревший курсор требует повторного запроса `around`.

Ответ: `items`, `beforeCursor`, `afterCursor`, `hasMoreBefore`, `hasMoreAfter`. DTO содержит message, стабильный mediaId, chatId/messageId/albumId, позицию в альбоме, тип, отправителя, время, подпись и защищённые URL. Неизвестные размеры обозначены `null`, а не вымышленными значениями.

Старый API без новых параметров продолжает возвращать массив сообщений для установленных клиентов. Добавлен частичный индекс `(chat_id,id)` по неудалённым сообщениям с вложением; миграция аддитивна.

Оригиналы выдаются через авторизованный `/api/files/{attachmentId}?message_id={messageId}`. Сервер заново проверяет членство, границу очищенной истории, соответствие файла сообщению, удаление и блокировку. Удалённое появление файла недоступно через его контекст, даже когда другая пересланная копия ещё разрешена. Само существование копии или аватара не отменяет проверку `message_id`. HTTP-ответы `private, no-store`; общедоступных обходных URL нет.

## Проверки

Релизная проверка: 170 Android unit/UI-тестов, 199 Node-тестов, React render-тесты, оба браузерных сценария, production-сборки Web/Windows и APK 0.12.76 (~103.1 МиБ, четыре ABI, ниже прежнего лимита 120 МиБ).

- Сервер: 205 вложений, середина истории, оба направления, границы альбома, видео, копии, повреждение/подмена курсора, другой чат/пользователь, удаление, очищенная история, отзыв доступа.
- Browser: реальный API + Chromium, 205 медиа, открытие середины, ограниченное число страниц, проигрывание настоящего WebM, жесты без случайной смены при зуме, подписи, скрытие панелей, live-удаление, кеш без сети и отказ после отзыва доступа.
- Android: Compose/Robolectric, курсорное окно, сохранение ID, удаление с подтверждением, ближайший сосед, отсутствие ложного итога, двойное касание, панорамирование, закрытие вниз и изоляция кеша.

## Границы этой версии

Нативного iOS-проекта в репозитории нет; на iPhone доступен Web-клиент. В этой среде нет физического Android/iPhone и Windows GUI: замеры 150 мс/60 FPS не выдаются за подтверждённый результат.

Выдача остаётся через защищённое локальное хранилище. Отдельные производные превью, видеотранскодинг, CDN/объектное хранилище и временные CDN-URL не подключены; DTO уже разделяет thumbnailUrl/fullUrl для дальнейшего подключения. Календарь с быстрым переходом к произвольной дате и точный переход к миниатюре на Android относятся к расширенному этапу. В Web есть переход от/к доступной миниатюре с учётом reduced motion. Правила одноразовых/исчезающих вложений не симулируются: таких типов в текущей модели нет.
