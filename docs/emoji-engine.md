# Emoji Engine — Web MVP, Волна 0.12.3

## Объём выпуска

| Этап ТЗ | Реализовано в 0.12.3 | Следующий этап |
|---|---|---|
| Web MVP | Unicode, статичные кастомные эмодзи внутри текста, редактор, каталог, наборы, установка/удаление, поиск, простые реакции, проверка ресурсов, права | Проверка на реальных браузерах и согласованная нагрузка VPS |
| Часть V1 | Создание статичных наборов, избранное/недавние, ключевые слова ru/en, ссылки на наборы, жалобы и блокировка | TGS/WebM, статусы профиля, адаптивная графика, полная авторская панель, переупорядочивание элементов |
| V2 | Не включён | Эффекты, их синхронизация, монетизация и AI-поиск |

Это развитие существующего React/Vite клиента, Node 24 и SQLite. Переход на PostgreSQL, TypeScript, Redis, очереди обработки анимаций и CDN не производится скрыто вместе с интерфейсом: это отдельный инфраструктурный этап. Нативный Android сохранён, новый Web-редактор в него не переносился. Windows использует общий React-интерфейс и получает эти изменения после сборки установщика.

## Редактор и отображение

`shared/emoji-text.mjs` — единая модель UTF-16, границ графем, вставки, удаления и пересчёта сущностей. `Intl.Segmenter` нужен на целевых современных браузерах. Категории Unicode организованы по модели 15.1; встроенная подборка небольшая, полный официальный каталог Unicode не включён. Любая корректная последовательность, введённая с клавиатуры или вставленная, остаётся текстом; её рисунок определяется системным шрифтом.

`EmojiEditor.jsx` хранит обычный текст и атомарные узлы кастомных эмодзи. HTML из буфера и drag-and-drop не вставляется: используется только текст. Поддерживаются курсор, выделение, Backspace/Delete целой графемы, IME, несколько строк, форматирование, редактирование и черновики. На широком экране Enter отправляет, Shift+Enter добавляет строку; на мобильном Enter добавляет строку. Лимит сообщения 4000 UTF-16 единиц, кастомных сущностей — 100.

Пример сообщения:

```json
{
  "text": "Привет 👍🏽",
  "emoji_entities": [{"id": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "start": 7, "length": 4}],
  "client_id": "globally-unique-retry-id-01"
}
```

Сервер проверяет диапазоны, пересечения, границы графем, точное совпадение fallback и доступ к набору. При удалении пробелов по краям смещения пересчитываются. Отправка, редактирование, пересылка и подпись альбома сохраняют сущности; повтор запроса не создаёт дубль. Получатель приватного эмодзи может читать и переслать авторизованное сообщение, но не получает доступ ко всему приватному набору.

`MessageText.jsx` пропускает текст и сущности через общий безопасный парсер: жирный текст, ссылки, цитаты и переносы совместимы с эмодзи. В коде отображается текстовый fallback. Одиночный эмодзи увеличивается до 64 CSS px. Недоступное/заблокированное/повреждённое изображение заменяется fallback. Старые inline-анимации отображаются fallback; существующие стикеры/GIF как вложения продолжают использовать свои проигрыватели.

Копирование всегда даёт `text/plain` с Unicode fallback. Между совместимыми редакторами дополнительно передаются `{version,text,entities}` в `application/x-volna-emoji+json`. Для кнопки копирования используется Web Custom Format только при поддержке браузером; иначе обычный текст. Буфер не содержит токенов или файловых ссылок. Сервер повторно проверяет вставленные идентификаторы.

## Медиа и первый набор

Новый API принимает статичный PNG 100×100 RGBA/совместимого PNG-представления, максимум 256 КиБ. Web-форма локально преобразует PNG/WebP до 5 МиБ в PNG 100×100 с сохранением пропорций и прозрачным полем; анимированный вход становится статичным кадром. Сервер проверяет ownership загрузки, сигнатуру, размеры, PNG chunk CRC, структуру, поддерживаемые цветовые форматы, ограниченную распаковку zlib, длину строк и фильтры. APNG, interlace, SVG, TGS и видео в новом Emoji API не принимаются. Антивирус, изолированный универсальный декодер и очередь обработки — будущий этап.

Старый API `/api/expressions` сохранён для совместимости; новые PNG-эмодзи в нём также проверяются, допустим холст до 512×512 для старых статичных наборов. Старые ресурсы автоматически не перекодируются.

Фирменный набор содержит 24 исходных статичных иллюстрации с названиями, fallback и ключевыми словами. Файлы: `server/assets/emoji/`. Воспроизводимый редактируемый источник: `scripts/generate-emoji-pack.py` (Python + Pillow, только для разработки). Сторонние изображения не используются. Версии для демо находятся в `client/public/demo/emoji/`.

## Хранение, миграции и кэш

Новые таблицы `emoji_asset_metadata`, `emoji_seeded`, `emoji_reports`, `emoji_audit`; к `expression_packs` добавлены `description`, `slug`, `status`, `updated`. Миграции добавочные, выполняются при старте, не сбрасывают пользователей и историю.

Первый набор получает фиксированные pack/item ID; media attachment IDs сохраняются после первой установки. Он автоматически устанавливается один раз для каждого пользователя. Удаление из установленных не меняет старые сообщения и не приводит к автоматической повторной установке. Удаление собственного набора — soft delete, ресурсы старых сообщений сохраняются. Логические ID элементов не переиспользуются.

Медиа загружаются через авторизованный `/api/files/{id}`. Web-кэш — только память вкладки: не более 8 МиБ и 256 записей, повторные загрузки объединяются, срок 60 секунд. Ресурсы истории подгружаются при приближении к viewport. Object URLs освобождаются. Выход из аккаунта и кнопка очистки кэша очищают emoji cache. Постоянного offline-кэша, CDN или гарантии работы без сети в этом выпуске нет.

## Каталог, реакции, права

`GET /api/v1/emoji/packs` — страницы по 20 наборов; `GET /api/v1/emoji/search` — по 60 элементов, offset до 10000. Поиск по названию/ключевым словам/fallback, точные совпадения имеют приоритет. Избранное, недавние и установка хранятся на сервере отдельно для аккаунта. Unicode избранное/недавние хранятся локально как настройки.

Приватный набор видит только владелец. Только владелец может переименовать/описать или удалить свой набор; builtin защищён. Жалоба содержит причину до 500 символов, одна на пользователя/набор. Права модератора задаются явно в окружении; жалобы и действия записываются на сервере. Блокировка запрещает выдачу ресурсов и очищает кэш подключённых Web-клиентов через SSE. После разблокировки изображения снова доступны. Полная админ-панель модерации не включена.

Реакции — одиночные Unicode-графемы с идемпотентным включением/выключением. По умолчанию до трёх разных реакций пользователя и до 20 разных типов на сообщение. Синхронизация — существующие `message-update` SSE; пользователи и счётчики видны в меню реакции. Кастомные реакции не включены.

Настройки `.env`, передаваемые Compose в server:

```dotenv
EMOJI_PACK_MAX_ITEMS=200
EMOJI_REACTIONS_PER_USER=3
EMOJI_REACTION_TYPES=20
EMOJI_MODERATOR_USER_IDS=
```

Последнее поле — числовые ID назначенных модераторов через запятую, не username. Для смены окружения пересоздайте сервер через скрипт обновления. Общий лимит API 240 запросов/минуту на аккаунт сохраняется, загрузки используют существующие квоты. В журнал не выводятся содержимое сообщений, clipboard или секреты.

## API

Машиночитаемое описание: `docs/emoji-openapi.json`. Все emoji endpoints требуют существующую сессию. Ошибки имеют `{error}` и HTTP 400/401/403/404/409/429; отсутствие приватного объекта обычно даёт 404.

| Метод и путь после `/api` | Назначение |
|---|---|
| GET `/v1/emoji/config`, `/v1/emoji/categories` | Возможности и категории |
| GET `/v1/emoji/search` | q, section=catalog/installed/recent/favorite, pack_id, offset |
| GET/POST `/v1/emoji/packs` | Каталог или создание с title, description, public, items, client_id |
| GET/PATCH/DELETE `/v1/emoji/packs/{id}` | Читать, изменить title+description, soft delete |
| POST/DELETE `/v1/emoji/packs/{id}/install` | Установить / удалить из установленных |
| POST `/v1/emoji/packs/{id}/report` | reason |
| POST `/v1/emoji/packs/{id}/moderate` | Модератор: status=blocked/published |
| GET `/v1/emoji/reports` | Модератор: последние 100 жалоб |
| POST `/v1/emoji/uploads` | Проверить attachment_id, загруженный через `/uploads` |
| GET `/v1/emoji/{id}` | Метаданные доступного эмодзи |
| POST `/v1/emoji/{id}/favorite`, `/use` | active / учёт выбора |
| POST `/chats/{chat}/messages`, `/album` | text + emoji_entities и прежние поля |
| POST `/messages/{id}/edit`, `/forward`, `/react` | Прежний контракт, edit сохраняет emoji_entities |

Ссылка на набор: `/app?emoji_pack={pack_id}`. После входа и выбора чата открывается соответствующая вкладка.

## Проверки и ручная приёмка

Автотесты: PNG, CRC/размер/повреждения; графемы/UTF-16/модификаторы/ZWJ/флаги; черновики; приватность/ownership; создание/повторы; установка/удаление; история/пересылка; подписи альбомов; лимиты реакций; модерация/аудит/fallback; демо. SSR проверяет реальные React-компоненты, форматирование с эмодзи, ARIA, категории и поле ввода. Production build проверяет импорт общего модуля.

Локальная smoke-нагрузка: `node scripts/bench-emoji.mjs`, 80 HTTP запросов, 8 одновременно, временная SQLite, mock SMS, чередование поиска и PNG. Это не оценка мощности вашего VPS и не замена согласованного нагрузочного теста.

Обязательная ручная проверка перед эксплуатацией: Chrome/Firefox/Safari и мобильный браузер, экраны 360/768/1280/1920 px, курсор до/после кастомного эмодзи, IME, выделение и Shift+Enter, копирование в обычный редактор и обратно, screen reader и Reduce Motion, получение на втором устройстве, холодный кэш и отсутствие сети. В данной среде нет браузера, Docker, Android SDK и Windows toolchain; реальную браузерную приёмку, APK/EXE и production-сервер здесь не проверяли.
