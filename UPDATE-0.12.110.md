# Волна 0.12.110 — надёжное завершение и диагностика звука

## Завершение при отсутствии Интернета

Android, Web и Windows сохраняют намерение завершить конкретный звонок до освобождения локальных ресурсов. Интерфейс закрывается сразу; если запрос не дошёл до сервера, отправка повторяется при восстановлении сети и во время работы приложения. После повторного запуска с тем же аккаунтом очередь также возобновляется.

В записи находятся только идентификаторы звонка и исходного устройства, причина завершения и служебные сроки повторов. Токены входа, SDP, содержимое сообщений и записи разговора не сохраняются. Очередь разделена по серверу и аккаунту, ограничена 16 командами и сроком 24 часа. Повторы используют исходный идентификатор устройства, даже если окно уже было перезагружено. Подтверждённые и окончательно отклонённые команды удаляются.

Пока команда ожидает отправки, устаревшее состояние сервера не открывает завершённый звонок снова. Перед новым исходящим вызовом клиент пытается завершить предыдущий; запоздалое завершение старого идентификатора не затрагивает новый звонок. В Web при недоступном локальном хранилище очередь работает в памяти до закрытия страницы. Если приложение закрыто, отправка возобновится при следующем запуске аккаунта; серверный срок освобождения звонка по-прежнему действует независимо от очереди.

## Пауза при HTTP 429

Сервер возвращает `Retry-After`, `retry_at` и `server_time`. Клиенты вычисляют паузу относительно времени сервера, поэтому неверные часы телефона не увеличивают её на часы. Опрос звонка, повторяемые команды и отправка диагностики соблюдают ограничение. Событие возвращения сети не обходит паузу 429 для отложенного завершения. Задержка очередного сетевого повтора учитывает оставшийся бюджет восстановления; после его истечения новая попытка не начинается.

Лимиты звонков и переписки остаются разделёнными, как в 0.12.109. Сетевые повторы не распространяются на окончательные ошибки владения звонком и доступа.

## Проверка аудиопотока

Добавлены отдельные счётчики входящих и исходящих **аудио** RTP-пакетов: видеопакеты больше не могут скрыть отсутствие аудио в диагностике. В журнале появляются события жизненного цикла:

- `audio_first_packet` — впервые обнаружены входящие аудиопакеты. `elapsed_ms` отсчитывается от подготовки медиаканала на этом клиенте, а не от серверного принятия вызова; у звонящего сюда может входить ожидание ответа.
- `audio_stalled` — после получения аудио счётчик не увеличивался не менее 20 секунд. Событие записывается один раз до следующего изменения потока.
- `audio_resumed` — аудиопакеты снова поступают. Сброс счётчика при смене потока сам по себе не считается возобновлением звука.

До первого пакета статистика проверяется примерно раз в секунду, затем примерно раз в пять секунд. Обычные отчёты статистики не отправляются чаще прежнего пятисекундного интервала. Это проверка получения пакетов, а не подтверждение воспроизведения динамиком. Молчание, выключенный микрофон и DTX не приводят к автоматическому разрыву или перезапуску звонка только по этим счётчикам.

Ошибки ICE-согласования теперь записываются с этапом `restart`, поколением ICE, типом ошибки и HTTP-статусом при наличии. Одинаковые частые сбои не заполняют журнал непрерывным потоком: отчёт ограничен частотой. Полные тексты исключений, адреса, пароли и SDP не добавляются.

## Обновление

Из `/root/volna-messenger`, где находятся `.env` и `compose.yaml`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.110 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.110-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Установите **Android 0.12.110 (12110) на оба телефона**, обновите Windows и перезагрузите Web после публикации. Если нужен только Android, замените `sh scripts/build-clients.sh` на `sh scripts/build-android.sh`. Команда создаёт резервную копию и сохраняет настройки, данные и артефакты. Для Windows-builder требуется 4 ГБ свободного места.

Для всех изменений нужны обновлённые сервер и клиенты. Очередь завершения не требует изменения схемы серверной базы. TURN-only, оригинальные звуки, эмодзи проверки и трёхминутный предел восстановления сохранены.

## Проверки

Прошёл 291 Node-тест и 251 Android-тест. Собраны Web, Windows renderer и проверочный APK 0.12.110 (12110).

Проверены сохранение команды при сетевой ошибке и после перезагрузки, исходное устройство повтора, изоляция аккаунтов/серверов, удаление подтверждённых команд, запрет обхода 429, ограничение срока хранения и отсутствие токенов в очереди. Серверная регрессия подтверждает: повторное завершение прежнего звонка не завершает новый вызов того же аккаунта.

В Chromium проверены Web и Windows: отклонённый звонок закрывается локально, не появляется снова из устаревшего ответа сервера и подтверждается после перезагрузки. Также проверены подготовка без микрофона, обычный интерфейс звонков и уведомления. Проверены аудиосчётчики, пауза/возобновление, сброс счётчика, диагностические фильтры, сетевые повторы и время сервера.

Физические телефоны и переключение Wi-Fi ↔ мобильная сеть в среде сборки недоступны. После обновления проверьте завершение без сети и новый вызов после её возвращения; журнал `/calllog` покажет доставку завершения и состояние аудиопотока.
