# Обновление Волны до 0.12.40

## Автоустановка при простое

Новая опция «Обновлять при простое» по умолчанию выключена. Windows: Настройки → Обновления; Android: Настройки → Обновления. Выбор сохраняется между обновлениями. При включении клиент скачивает обновление заранее. Windows устанавливает его после 10 минут без клавиатуры/мыши; Android — после 10 минут с выключенным или заблокированным экраном, пока работает фоновая служба сообщений. Звонки и отправка вложений блокируют установку. После установки клиент запускается снова.

На Android 12+ запрашивается разрешённое системой самообновление без действий пользователя (`USER_ACTION_NOT_REQUIRED`, `UPDATE_PACKAGES_WITHOUT_USER_ACTION`). Требуется ранее выданное разрешение на установку приложений для Волны. Прошивка может потребовать подтверждение: тогда автоматическая установка останавливается, появляется уведомление, пользователь устанавливает уже скачанный APK вручную. Без работающей службы или после принудительной остановки Android фоновая проверка не выполняется; при следующем запуске снова будет доступна проверка. Проверка в службе — каждые 15 минут, загрузка проверяется SHA-256.


Оформление сохраняется на сервере в аккаунте отдельно для Android, Web и Windows. При входе возвращаются тема, цвета, шрифт, размер, плотность и эффекты. Web/Windows также сохраняют обои; Android — библиотеку тем и оформление чатов. Имя, ник и аватар продолжают храниться в существующем профиле.

Запустите блок в прежнем каталоге Волны с `compose.yaml` и `.env`. Перед заменой исходников создаётся резервная копия данных. `.env`, данные и подпись Android сохраняются; не удаляйте `artifacts/android-home`. `VITE_API_URL` должен указывать на ваш настоящий HTTPS API. Облачные тестовые сборки с `example.invalid` устанавливать не нужно.

```sh
(
  set -eu
  test -f compose.yaml && test -f .env
  volna_update_dir=$(mktemp -d)
  trap 'rm -rf "$volna_update_dir"' EXIT
  git clone --depth 1 --branch v0.12.40 \
    https://github.com/andluk87/volna.git "$volna_update_dir/source"
  git -C "$volna_update_dir/source" archive \
    --output="$volna_update_dir/source.tar" HEAD
  sh "$volna_update_dir/source/scripts/backup.sh"
  tar -xf "$volna_update_dir/source.tar" -C .
  VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh
)
```

После сборки установщик Windows доступен на `/download`; установленный Windows-клиент получает версию 0.12.40 через штатную проверку обновлений. Web обновляется на сервере вместе с сервисами. Если открыта старая вкладка, перезагрузите её. Настройки, аккаунты и переписки сохраняются. Android пересобирается с прежней подписью, поэтому устанавливается поверх существующего приложения. Канал новостей создаётся после запуска обновлённого API.

После обновления войдите в каждый используемый клиент и оставьте его подключённым к серверу: это создаст первую резервную копию текущего оформления. До этого обновления оформление было локальным; удалённые ранее настройки восстановить нельзя. При недоступном сервере появится сообщение в настройках оформления, сохранение повторится автоматически.

Для проверки измените тему, шрифт и размер, дождитесь успешной синхронизации, затем войдите в тот же аккаунт в чистом браузере/после переустановки. Windows и Web используют отдельные профили; новый клиент другой платформы начинает со своих стандартных настроек. Android сохраняет также расписание темы, эффекты стекла, библиотеку тем и оформление отдельных чатов.

Синхронизируются только настройки внешнего вида, а не пароли, токены, системные разрешения или кэш переписок. Файл обоев ограничен 5 МБ; весь профиль — 12 МБ. При превышении Android показывает ошибку сохранения: уменьшите размер обоев или удалите неиспользуемые темы. Несохранённые изменения нужно отправить на сервер до удаления приложения.

Проверки: серверное сохранение после перезапуска, изоляция аккаунтов/платформ и валидация; Web/Windows с чистым хранилищем, обои и отказ сети; Android — сборка и unit tests. Системную переустановку Windows 10/Android нужно дополнительно проверить на устройствах. Облачный тестовый APK использует `example.invalid`; для установки соберите клиент блоком выше с настоящим API и прежней подписью.

## Звук исходящего звонка

До подтверждения входящего вызова устройством получателя играет короткий сигнал установки соединения. Затем идут обычные гудки и надпись «У собеседника входящий звонок…». Ответ/соединение/завершение выключают эти сигналы. Подтверждение отправляют Android, Web/Windows, уведомления фоновых аккаунтов и Web service worker после показа push. Оно не принимает звонок и не закрепляет его за устройством.

Гудки подтверждают доставленный входящий вызов, а не слышимость динамика: режим без звука и системное подавление уведомлений определяет устройство. Старый клиент без подтверждения сохраняет сигнал соединения до ответа; обновите оба клиента. Push использует отдельное краткоживущее разрешение только на подтверждение этого звонка, не токен аккаунта. Истёкшее/завершённое подтверждение отклоняется.

Android автоматически проверяет разрешения после обновления. При отсутствии полноэкранного доступа или уведомлений открывается окно включения. Выдать системное разрешение без участия пользователя Android не позволяет.

## Входящий вызов невыбранного аккаунта

После обновления проверьте вызов на второй аккаунт при выбранном первом: в Android с открытым приложением и с блокировкой, в Web с открытой вкладкой, в Windows также со свёрнутым окном. Видны аккаунт, собеседник и кнопки ответа/отклонения. Отказ должен завершать именно этот вызов. Переключение аккаунта Web/Windows сохраняет обработчик звонка. На Android открытие чата после ответа переключает интерфейс на аккаунт вызова; переписка остаётся за блокировкой.

Полноэкранный запуск требует выданного системного разрешения Android и разрешённых уведомлений канала соответствующего аккаунта. ОС определяет запуск поверх блокировки; сборка проверена, физические Samsung/Windows нужно проверить отдельно. В закрытом браузере Web остаётся системное push-уведомление; отобразить интерфейс закрытой вкладки браузер не позволяет. Одновременные аудиоразговоры на двух аккаунтах не запускаются, текущий вызов сохраняется.

## Обновления и разрешения

Android автоматически скачивает и проверяет APK. Внизу предлагаются «Обновить сейчас» и «Не сейчас»; второй вариант только скрывает предложение для этой версии и не устанавливает APK. В настройках остаются проверка вручную, установка и отдельный явный выбор установки при следующем запуске. Старое выключенное значение автоматической загрузки переводится во включённое один раз при переходе на 0.12.40; пользователь может изменить настройку позже.

Установка выполняется через PackageInstaller. На Android 14+ сохраняется уже выданный доступ к USE_FULL_SCREEN_INTENT, а ранее запрещённый доступ не включается автоматически. Основание: [документация SessionParams.setPermissionState](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setPermissionState(java.lang.String,%20int)) разрешает обычным установщикам задавать этот специальный доступ. Системное подтверждение установки остаётся обязательным. Новый механизм сохранения доступа действует при обновлениях, запускаемых из 0.12.40 и следующих версий; первое обновление старым установщиком может ещё потребовать повторного включения.

После установки callback PackageInstaller открывает отдельную закрытую для внешних приложений activity и возвращает на главный экран. MY_PACKAGE_REPLACED служит резервным механизмом. Если Android/OEM блокирует запуск из фона, остаётся уведомление «Обновление установлено — открыть Волну». При переходе со старого установщика учитывается APK текущей версии в собственном каталоге загрузок. Повторное открытие по двум сообщениям установщика исключено. Случайные старые/посторонние установки не запускают приложение по сохранённому запросу.

Windows автоматически загружает обновление, предлагает установку внизу и использует force-run после установки. Согласие на микрофон/камеру хранится в пользовательском каталоге приложения, а не в памяти. Оно не выдаётся другим сайтам. Системный запрет Windows на микрофон остаётся отдельной настройкой ОС. Обычное обновление поверх приложения сохраняет каталог; удаление данных или установка с другой подписью не сохраняют права.

## Huawei Watch Ultimate

На скрине Huawei Watch Ultimate показывает «Неизвестный номер». Для часов, определяющих контакт по Bluetooth-номеру, передаётся реальный номер из сохранённого контакта аккаунта, дополнительно — его личное имя/имя телефонной книги. Username и синтетические числа не используются. Номер скрытого чужого профиля не извлекается. Если у контакта нет известного номера или прошивка игнорирует VoIP-имя, часы могут продолжать показывать «Неизвестный номер»: приложение не может изменить парсер прошивки часов. Контакт должен иметь настоящий телефон и быть доступен/синхронизирован в телефонной книге/Huawei Health.

## Проверка

Проверьте на Samsung: автозагрузку, нижнее предложение, отказ без установки, ручную проверку, подтверждение установки, сохранение полноэкранного доступа при следующем обновлении из нового установщика и возврат в приложение. На Windows: разрешите микрофон, закройте/откройте клиент, затем обновите и повторите звонок. На часах: звонок от сохранённого контакта с реальным номером. В облаке доступны тесты и сборки; физические установщики, динамики и часы должны быть проверены на устройствах.

При ошибке `no space left on device` используйте [продолжение без пересборки клиентов](UPDATE-DISK-RECOVERY.md).

## Уведомления на часах

Уведомления сообщений Android содержат небольшой системный значок и цветное изображение Волны, действие RemoteInput «Ответить». Ответ отправляется в исходный чат от аккаунта, которому пришло сообщение, без открытия приложения и переключения аккаунта. Права отправки проверяет сервер; для чатов с известным запретом отправки действие не предлагается. При ошибке сети уведомление остаётся и сообщает о неотправленном ответе. Повтор одного ответа защищён идентификатором от дублирования.

Huawei Health и прошивка Huawei Watch Ultimate определяют, будут ли показаны цветное изображение и поле ввода. В Huawei Health включите уведомления Волны и, если прошивка предлагает, быстрые ответы. Приложение не может заставить часы поддерживать сторонний RemoteInput. Нужно проверить на реальных часах: значок, текстовый ответ, невыбранный аккаунт, отсутствие сети и отсутствие повторной отправки.

## Круглый значок и уведомления

Исправлен старый системный ресурс Android: вместо самолётика на непрозрачном квадрате — белые волны в круглом контуре на прозрачном фоне. Системный значок Android использует альфа-маску и может быть одноцветным. Цветное круглое изображение с волнами и чукотским фоном теперь передаётся и в сообщения, и в уведомления входящих/активных звонков; уведомления разрешены для передачи на другие устройства (`localOnly=false`).

Круглые значки с прозрачными углами используются в Android, Web и Windows. Android имеет отдельный `roundIcon`, прозрачный фон adaptive icon и варианты для тематических значков. Web сохраняет отдельную непрозрачную картинку для системной маски PWA. Форму внешней маски adaptive/PWA определяет оболочка ОС.

Huawei Health/прошивка часов выбирают, показывать значок приложения, системный значок, цветное изображение или общий символ для неизвестного приложения. Передача всех стандартных полей Android исправлена; принудительно назначить значок в прошивке Huawei нельзя. Проверьте новое уведомление после установки 0.12.40. Если Health сохранил старую картинку, можно выключить и включить уведомления Волны в Huawei Health; переустанавливать Волну и повторно выдавать все Android-разрешения не требуется. Значок в собственном Bluetooth-экране звонка часов также определяет прошивка.
