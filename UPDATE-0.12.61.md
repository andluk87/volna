# VLN 0.12.61 — обновление Windows, QR и сохранение входа

## Что изменилось

В Windows при доступном обновлении внизу списка чатов появляется полоса «Обновить VLN», как на примере пользователя: на ширину колонки чатов, без всплывающей карточки. При загрузке виден процент, при ошибке — повторная попытка. Полоса работает с папками, без папок и при пустом списке. Установка не прерывает звонок, передачу файлов или сохранение refresh-токенов. До установки 0.12.61 старый Windows-клиент использует прежний интерфейс обновления.

В Android скан QR камерой сразу выполняет проверку кода и привязку Web/Windows без дополнительной кнопки подтверждения. Ошибочный, просроченный или уже использованный код не проходит проверку сервера. Заморозка анализатора предотвращает повторную отправку одного скана. Простое открытие ссылки входа по-прежнему требует подтверждения; это отдельный путь, не сканирование камерой.

## Сохранение сеансов

- Windows повторяет восстановление при временной ошибке сети/защищённого хранилища, вместо показа QR-входа. Аккаунты остаются в профиле `%APPDATA%/Volna`, зашифрованы Windows safeStorage и записываются атомарно.
- Общий процесс Electron сериализует refresh для окон одного аккаунта. Новые токены сохраняются до ответа окнам. Частичный снимок дочернего окна не удаляет остальные аккаунты и не заменяет более свежие токены. Если защищённая запись временно не сработала после ротации, новый токен остаётся в памяти основного процесса для повторной записи; установка до её завершения блокируется. Установка обновления ждёт завершения refresh.
- Android сохраняет прежние идентификатор приложения и ключ Keystore. При установке APK из приложения текущий refresh сначала завершается и записывается, затем новые refresh приостанавливаются до результата установки. Отмена/ошибка установки восстанавливает их работу. Первичная отметка миграции авторизации теперь пишется синхронно.
- Android выходит только по фактическому ответу об истёкшей/недействующей авторизации, а не по совпадению текста сетевой ошибки с «401» или «Войдите».
- Перезапуск сервера с существующей SQLite-базой сохраняет Android- и Windows-refresh-сеансы и ключ авторизации: это проверено тестом перезапуска. Истечение срока или явный отзыв устройства остаются основаниями нового входа. Уже потерянные/отозванные токены обновление восстановить не может.

## Обновление Android, Windows и сервера одной командой

Запустите в прежнем каталоге сервера с действующим `.env`, `compose.yaml` и `artifacts`. Команда использует имеющиеся настройки сборки, данные и ключ подписи Android:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.61 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.61-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; sh scripts/build-clients.sh )
```

Скрипт делает резервную копию, переносит старые Android-исходники в `backups/android-source-0.12.61-XXXXXXXX/src`, получает фиксированный тег и собирает оба клиента. Затем публикует APK, Windows-установщик и ленту обновления, обновляет сервер/Web один раз и проверяет загрузки. Не переносите обновление в новый каталог: это сохраняет прежний Compose-проект и том с базой.

После успеха установите Android **0.12.61 (12061)** и Windows **0.12.61** поверх прежних версий. Адреса загрузок: `/download/volna-android.apk` и `/download/volna-windows.exe` на вашем сервере.

## Проверка

Локально прошли сборка Android APK и полный набор из 123 Android JVM/UI-тестов, 24 Node-проверки обновлений/сеансов/QR, production-сборка Web и браузерные проверки полосы обновления и восстановления сеансов после сбоев. Windows-интерфейс проверяется в Chromium с имитацией Electron IPC, сам Windows-установщик и Android-камера требуют проверки на устройствах.
