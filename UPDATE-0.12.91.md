# VLN 0.12.91 — локальная large-v3 и музыкальный плеер

Основная локальная модель распознавания — **Whisper large-v3**, CPU `float32`, `beam=5`, 8 потоков. Аудио остаётся на сервере: интернет используется для однократного скачивания весов, а не для передачи записей стороннему API. На показанной виртуальной машине вычислительная GPU не обнаружена, поэтому профиль использует CPU.

При долгой загрузке основной модели сервис пробует ранее скачанную `base` **только из кэша**, без отдельного скачивания. Пока она используется, health показывает `state:degraded`, `active_model:base`; качество в этот момент соответствует резервной модели. После успешной загрузки основной — `state:ready`, `active_model:large-v3`. Само `ready:true` ещё не означает, что работает large-v3: проверяйте имя активной модели. Если резервной модели в кэше нет, распознавание будет недоступно до загрузки основной.

Из прежней папки проекта с `compose.yaml` и `.env`, одной вставкой:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.91 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.91-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; python3 scripts/improve-transcription.py; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Команда обновляет стандартные старые профили `.env` (tiny/base/small/medium/large-v1/large-v2 → large-v3; int8 → float32; 4 CPU-потока → 8). Пользовательские локальные модели и нестандартные настройки сохраняются. Предыдущий `.env` сохраняется приватно в `backups/`. Если ранее выполнялась временная команда `WHISPER_MODEL=base docker compose up …`, это обновление применит профиль из `.env`.

Полная модель — несколько гигабайт весов и значительный расход RAM/CPU; первый запуск может быть долгим. Не считайте её скачанной только по HTTP 200 health. Проверить фактическую готовность:

```sh
docker compose exec -T transcription python -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:8000/health").read().decode())'
docker compose logs --since=20m --timestamps transcription
```

Для оценки нового качества дождитесь `active_model:large-v3`, `primary_state:ready`, затем нажмите «Распознать заново» под старым текстом. При `active_model:base` работает резерв. В health также видны CPU, точность, число потоков, время загрузки и безопасный код ошибки. Пустой ответ 503 больше не выдаётся за нормальную загрузку; отдельные сообщения объясняют нехватку диска, права кэша и затянувшееся скачивание. Увеличены таймауты тяжёлого распознавания: API до 15 минут, Android и прокси — 16 минут. Качество/скорость на пользовательском аудио в этой среде не измерялись.

Обновите Android и Windows до 0.12.91, в Web перезагрузите страницу. Музыкальное сообщение теперь открывает **компактный плеер над чатом**, как на присланном примере: пауза, предыдущий/следующий трек, перемотка, громкость, перемешивание, повтор очереди/одного трека, скорость и закрытие. В Android дополнительные параметры раскрываются отдельной кнопкой. Трек продолжает играть при переходе между чатами; очередь состоит из загруженных музыкальных сообщений исходной переписки. Голосовые в эту очередь не попадают.

Музыка останавливается при смене аккаунта/выходе и звонке, Web/Windows не позволяют запустить её во время вызова. Android учитывает потерю аудиофокуса и отключение гарнитуры. Автоматическое обновление откладывается, пока плеер открыт. Файл скачивается перед началом воспроизведения; потоковая передача и отдельный Android foreground music service/lock-screen player в этот выпуск не добавлены.

Проверки: 230 Node-тестов, 212 Android-тестов, 13 Python-тестов; production-сборки Web/Windows renderer и APK 103.28 МиБ. Проверены реальный аудиофайл в полном Web/Windows-приложении, смена чата/аккаунта, очередь, громкость, скорость, повтор и запрет музыки во время звонка; Android MediaPlayer через Robolectric и интерфейс панели; переход резервной модели на основную, отказ/кэш без скачивания, таймауты и сборки. На физическом Android/Windows, GPU и с реальными весами large-v3 проверка здесь не выполнялась.
