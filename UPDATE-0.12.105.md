# Волна 0.12.105 — меньше пауз при соединении звонка

В четырёх последних звонках из журнала Android 0.12.104 подключение после принятия заняло примерно 5–9 секунд. Во всех четырёх случаях у одной стороны в первом SDP не было relay-кандидатов, поэтому выполнялось дополнительное согласование ICE. Время ожидания ответа человека в эти цифры не включено.

В клиентах обнаружены дополнительные программные паузы: сигнал SSE мог быть обработан, пока ещё выполнялись подготовка звонка, HTTP-запрос или согласование WebRTC. Следующий шаг тогда ждал очередного двухсекундного опроса. При восстановлении таких последовательных шагов несколько.

Изменения в Android, Web и Windows:

- Сразу после отправки первоначального offer/answer продолжается получение актуального состояния звонка.
- После ответа сервера на шаг ICE restart / answer / media-state запускается следующий шаг согласования, без ожидания двухсекундного таймера.
- Web/Windows сохраняют сигнал повторного опроса, поступивший во время уже выполняющегося запроса; одновременно два опроса не запускаются.
- Запасной интервал во время вызова, соединения и восстановления уменьшен с 2 секунд до 500 мс. Для установленного разговора и отсутствующего звонка сохраняются 2 секунды.
- Подтверждённое состояние без изменений не порождает непрерывный цикл запросов.

TURN-only, наборы кандидатов, порядок offer/answer, поколения ICE и тайм-ауты безопасности сохранены. Само получение TURN-кандидатов всё ещё зависит от сети: выпуск убирает лишнее ожидание в клиенте, но не обещает одинаковое время подключения в любых условиях. Ускорение на физических телефонах нужно измерить новым журналом после обновления.

## Обновление

Из `/root/volna-messenger`, где находятся `.env` и `compose.yaml`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.105 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.105-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Собираются Android, Windows и Web; данные, `.env` и резервные копии сохраняются. Для Windows-builder требуется 4 ГБ свободного места. Если сейчас нужно обновить только Android, замените в команде `sh scripts/build-clients.sh` на `sh scripts/build-android.sh`.

Установите **Android 0.12.105 (12105) на оба телефона**. Для Windows/Web ускорение требует нового клиента или перезагрузки страницы после публикации. Бот и ссылка на журнал остаются прежними: после теста пришлите действующую ссылку или создайте новую через меню бота → `/calllog`. Для оценки сравнивается время от `call.accepted` до `call.connected` и клиентских `rtc.state.connection:connected`, отдельно от ожидания ответа человека. Клиентское `client_time` помогает учитывать задержку доставки диагностических событий.

## Проверки

Прошли 268 Node-тестов и 239 Android-тестов. Собраны Android APK, Web и Windows renderer.

Проверяются немедленное продолжение после мутации сигнализации, отсутствие пробуждения на неизменившемся состоянии, запрет действий завершённого звонка, отсутствие параллельных переговоров, потерянные HTTP-ответы и повторные answer. Android-тесты проверяют быстрый интервал соединения/восстановления и обычный интервал установленного разговора/простоя. Дополнительно выполняются полный набор серверных тестов, проверки интерфейса Web/Windows, сборка клиентов и проверка версии APK. Физическая сеть пользователя в среде сборки недоступна.
