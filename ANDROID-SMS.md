# SMS-вход Android · Волна 0.12.17

Экран номера: поиск страны, код страны, форматирование номера, проверка длины по телефонным планам. Экран подтверждения: скрытая часть номера, шесть ячеек кода, автоматическая проверка после шестой цифры, таймер повторной отправки. Ведущие нули сохраняются. Повторная отправка выполняется только по действию пользователя.

## Автоматическое получение

1. Android вычисляет 11-символьный SMS Retriever хеш по `dev.volna.messenger` и фактическому сертификату APK.
2. Приложение сверяет его с `GET /api/auth/config`, регистрирует приёмник с `SmsRetriever.SEND_PERMISSION` и `RECEIVER_EXPORTED`, запускает Retriever до запроса отправки.
3. Backend принимает только хеши из `ANDROID_SMS_APP_HASHES`. SMS нового Android имеет формат:

```text
001234 твоя волна Попытка: abcdefgh AbCdEfGhIjK
```

Хеш в конце строки здесь — пример. Переносов строк в SMS нет. Метка попытки — первые восемь символов случайного `challenge_id`. Формат ограничен 140 байтами UTF-8. Код генерируется и проверяется сервером; хранится HMAC, не открытый OTP.

4. Приёмник передаёт сообщение в строгий парсер. Принимаются только собственный формат, текущая метка и ожидаемый хеш. Код сохраняется только в оперативной памяти и сразу проверяется сервером.
5. При успехе ожидание прекращается, код удаляется, сеанс сохраняется существующим менеджером Android Keystore. Основной интерфейс открывается автоматически.

Если хеш APK ещё не зарегистрирован, применяется SMS User Consent: Android может попросить разрешение на одно собственное SMS. Отказ сохраняет ручной ввод. Без совместимых Google Play services доступен ручной ввод. `READ_SMS` и `RECEIVE_SMS` не добавлены; SMS-хранилище не читается. Retriever ожидает до пяти минут; срок OTP и ограничения устанавливает сервер.

## Хеш APK и подпись

Обычный `sh scripts/build-android.sh` теперь:

- проверяет подпись собранного APK через `apksigner verify`;
- вычисляет хеш из полного DER-сертификата, а не его fingerprint;
- экспортирует `artifacts/Volna-sms-app-hash.txt`;
- добавляет проверенный хеш в `.env`: `ANDROID_SMS_APP_HASHES`;
- сохраняет уже зарегистрированные хеши и существующий ключ APK;
- при обновлении передаёт список серверу через Docker Compose.

Не удаляйте `artifacts/android-home`: там находится существующий debug signing key, необходимый для установки обновления поверх прежнего APK. Если используете release-подпись или Google Play App Signing, добавьте хеш **фактически распространяемого** APK. Хешы debug, release и Play могут различаться.

Для APK со своей подписью:

```sh
python3 android-native/scripts/sms-app-hash.py \
  --apksigner /ПУТЬ/К/ANDROID_SDK/build-tools/36.0.0/apksigner \
  --package dev.volna.messenger /ПУТЬ/К/ПРИЛОЖЕНИЮ.apk
```

Добавьте выданный хеш в `ANDROID_SMS_APP_HASHES` через запятую и пересоздайте server с используемыми Compose-файлами. Хеш не является секретом. Нельзя копировать пример из документации вместо вычисления подписи.

## API

Все методы ниже — POST JSON через HTTPS. Старые `/api/auth/sms/request` и `/verify` сохранены для прежних APK; их SMS и SMS администратора сохраняют прежний формат `123456 твоя волна`.

| Метод | Тело запроса | Результат |
|---|---|---|
| `/api/v1/auth/otp/start` | `phone_e164`, `platform: android`, `locale: ru`, `request_id`, `app_hash` | Новая попытка или результат уже выполненного запроса |
| `/api/v1/auth/otp/resend` | `challenge_id`, новый `request_id` | Новый код и метка, предыдущий код недействителен |
| `/api/v1/auth/otp/verify` | `challenge_id`, `code` | Сеанс или контролируемая ошибка |
| `/api/v1/auth/otp/status` | `challenge_id` | Статус, сроки, скрытый номер; без OTP |
| `/api/v1/auth/otp/cancel` | `challenge_id` | Отмена текущей попытки |

`request_id`: 16–80 символов ASCII `[A-Za-z0-9_-]`, Android использует UUID. При сетевой ошибке отправки тот же ID сохраняется и используется для повторного запроса. Пока исходный запрос выполняется, возвращается `REQUEST_IN_PROGRESS`; автоматического повторного SMS нет. При принятом запросе повтор возвращает ту же попытку без нового SMS.

Ответ попытки: `challenge_id`, `masked_phone`, `otp_length`, `expires_at`, `resend_available_at`, `server_time`, `status`, `sms_nonce`, `sms_retriever`. Сроки — Unix milliseconds. Android преобразует их в монотонные локальные таймеры и сверяет статус при возвращении в приложение. Код не входит в сохранённое состояние экрана.

Ошибки: `INVALID_CODE`, `CODE_EXPIRED`, `ATTEMPTS_EXCEEDED`, `CHALLENGE_NOT_FOUND`, `RATE_LIMITED`, `SMS_UNAVAILABLE`, `REQUEST_IN_PROGRESS`, `REQUEST_ALREADY_PROCESSED`. Для ограничений возвращаются `retry_at` и `server_time`. Начальные ограничения: OTP пять минут, повтор не раньше 60 секунд, максимум пять неверных кодов; действуют также суточные/часовые лимиты установки.

## Проверка на настоящем телефоне

Сборка и автоматические тесты не подтверждают реальную доставку и работу Google Play services. После установки APK на физический телефон проверьте:

1. Версия APK 0.12.17, хеш присутствует в конфигурации сервера, номер принадлежит телефону.
2. С Google Play services: после «Продолжить» приходит SMS с меткой и хешем; вход происходит без нажатия кнопки подтверждения.
3. Без Google Play services / с отказом Consent: шестую цифру можно ввести или вставить вручную; проверка запускается автоматически.
4. Повторное SMS и SMS предыдущей попытки не создают второго входа. Возврат к номеру прекращает обработку предыдущей попытки.
5. Неверный код очищает поле; после пяти неверных попыток нужен новый код. Повторная отправка доступна после серверного таймера.
6. При отключённой сети показывается понятная ошибка; проверку полученного кода можно повторить до его истечения. Свернуть/вернуть приложение и закрыть процесс/открыть снова: нет автоматических повторных отправок.
7. Проверить две SIM, светлую/тёмную темы, крупный шрифт и TalkBack. Не отправлять номера, SMS-коды или тексты SMS в журналы и отчёты.
