# Контакты и видеозвонки 0.12.20

## Клиенты

Реализовано для Android Kotlin/Compose, Web и Windows/Electron. iOS-клиента в этом репозитории нет; серверный API можно использовать при его разработке.

Android предлагает импорт только после согласия пользователя и разрешения READ_CONTACTS. Разрешение WRITE_CONTACTS не используется. Импорт нормализует номера в E.164, объединяет дубли и поддерживает до десяти номеров записи. Изменения отслеживаются ContentObserver и при возврате в приложение. Отзыв разрешения прекращает чтение; ручные контакты и ранее синхронизированная книга доступны. Отключение переключателя прекращает импорт для аккаунта. Удаление импортированных данных отключает импорт для аккаунта, меняет epoch и блокирует повторную загрузку старым устройством до нового согласия.

Web использует системный выбор контактов там, где браузер поддерживает Contact Picker; браузер не даёт постоянного наблюдения всей телефонной книги. В Windows доступны ручное добавление, поиск и серверная книга, синхронизированная с Android.

Имена: личное имя → имя из книги → имя профиля → username. Личное имя хранится у владельца, не меняет чужой профиль; «Сбросить» возвращает имя из книги/профиля. Переименования без сети сохраняются локально и отправляются при восстановлении связи. Конфликт версии не перезаписывает новое имя другого устройства: очередь остаётся и показывает ошибку до повторного редактирования.

## API и приватность

Все маршруты требуют сеанса владельца:

- `GET /api/contacts/book?since=0` — книга или изменения, включая deleted-записи; версия, epoch, настройки и linked_user_id.
- `POST /api/contacts/settings` — enabled, discovery, presence. discovery/presence независимо принимают everyone / contacts / nobody.
- `POST /api/contacts/sync` — device_id, epoch, base_version, contacts (до 40 записей), removed (до 100 источников). Каждый источник имеет source_id, phone_numbers, phonebook_name. Неверная версия/epoch возвращает 409.
- `POST /api/contacts/manual` — phone_numbers и phonebook_name. Ручная запись сохраняется при очистке импорта.
- `POST /api/contacts/link` — user_id: приватная запись известного пользователя без раскрытия его номера.
- `POST /api/contacts/:id/name` — version и custom_name; пустое имя сбрасывает переименование.
- `POST /api/contacts/:id/delete` — version; удаление записи не удаляет чат.
- `POST /api/contacts/purge` — confirm:true; удаляет импортированные номера/имена/источники, оставляет ручные записи, личные имена и чаты.
- `GET /api/users?q=НОМЕР` — только точное совпадение подтверждённого номера; незарегистрированный и запрещённый для поиска номер дают одинаковый пустой результат. «Мои контакты» означает книгу того пользователя, которого ищут.
- `POST /api/auth/phone/change/request` и `/verify` — смена номера из текущего сеанса; SMS-сессия привязана к владельцу и цели, проверка принимает sms_session_id и code. ID, история и личные связи остаются прежними; занятый номер отклоняется.

POST контактов может передавать request_id (16–80 символов латиницы, цифр, `_`/`-`). Повтор того же запроса возвращает текущее состояние и не откатывает новое имя. Повтор ключа с другим телом возвращает 409. Клиенты используют версии и очередь. События SSE contacts отправляются только владельцу; другой сеанс обновляет книгу. Источники разных устройств объединяются и не удаляют друг друга. Лимит активной книги — 5000 записей, устройств — 20; новые уникальные поисковые номера ограничены 2000 в сутки, точный поиск — 5 запросов в минуту. Метаданные поисковых лимитов содержат HMAC, а не исходный номер, удаляются через сутки; метаданные повторов — через семь дней, неактивных устройств — через 180 дней.

Номера собственной книги доступны её владельцу; публичные объекты пользователей не раскрывают телефоны. Стабильная связь хранится по ID, а не username/номеру. Смена номера не переназначает существующие контакты новому владельцу старого номера. Обычный вход по SMS на неизменённый номер не позволяет отличить прежнего владельца от нового: полной защиты истории при повторной выдаче номера без дополнительного фактора нет. Обязательный пароль не вводится по решению пользователя.

Используйте штатный HTTPS gateway для удалённых клиентов. База и резервные копии содержат личную книгу: доступ ограничивается администратором сервера. Очистка текущей книги не уничтожает старые резервные копии; сроки удаления архивов определяет администратор.

## Видео

Основное видео и маленькое окно меняются касанием без создания нового WebRTC соединения. Позиция маленького окна нормализована относительно области звонка и ограничена её границами. Android сохраняет расположение при сворачивании и изменении ориентации; локальная фронтальная камера отражается, задняя — нет. Отключение камеры показывает заглушку и оставляет звук. Касание свободного места переключает управление. Повторное подключение показывается в статусе звонка.

Android Picture-in-Picture доступен на поддерживаемой системе с Android 8+, для соединённого видеозвонка; на Android 12+ включён автоматический переход при уходе на главный экран. Web предлагает системное видеоокно, если браузер поддерживает Picture-in-Picture. Отказ в разрешении камеры позволяет использовать звук.

## Проверки

Автоматически: 125 серверных тестов, 43 Android unit-теста, APK 0.12.20 (12020) с проверкой версии и подписи, Web production build и React render, Windows NSIS-установщик 0.12.20 с проверкой SHA-512, размера и blockmap. QA-сборки используют тестовый API и не публикуются как приложения вашего сервера. Дополнительный `node tests/contact-video-ui.mjs` требует установленные зависимости client и Chromium (`CHROMIUM_PATH` при необходимости). Он проверяет две сессии книги, переименование без сети, перестановку окон, границы перемещения, сохранение после сворачивания, выключение камеры и завершение без JS-ошибок. Камера использует тестовый источник Chromium; состояние соединения имитируется, поскольку политика облачного Chromium запрещает UDP. Этот сценарий не подтверждает обмен медиаданными через интернет.

На двух реальных устройствах проверьте:

1. Видео Android ↔ Android и Android ↔ Web: звук и изображение в обе стороны, камера до/после ответа, отказ в разрешении, смена камеры, отключение одной/обеих камер и восстановление сети.
2. Перестановку окон касанием, перемещение по всем границам, поворот телефона, сворачивание, PiP, возвращение и завершение из другого клиента. Положение и соединение должны сохраняться.
3. Аудиовыход: разговорный динамик/громкая связь/гарнитура. Датчик приближения гасит экран только при разговоре через телефонный динамик без видео/показа экрана. Повторите с заблокированным экраном и входящим звонком.
4. Добровольный импорт, отказ/отзыв разрешения, изменение/удаление контакта, несколько номеров, одинаковый номер у двух записей, второй телефон и новый зарегистрированный пользователь.
5. Имя в чате, профиле, списке контактов, истории звонков и уведомлении. Переименование без сети, конфликт двух устройств, удаление импорта и невозможность старого устройства загрузить книгу обратно без нового согласия.
6. Поиск по номеру без username с каждой политикой discovery; независимые политики presence; SMS-смена номера сохраняет историю и не объединяет аккаунты.

В облаке нет телефона или эмулятора; эти аппаратные проверки здесь не выполнены.
