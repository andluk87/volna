# Волна 0.12.111 — повтор создания звонка после тайм-аута

В новом журнале Android 0.12.110 три раза завершил создание звонка ошибкой примерно через 30 секунд. В соответствующем интервале сервер не зарегистрировал `call.created`. Ошибка произошла до согласования WebRTC; «Освобождение аудиоустройства» — последующая очистка ресурсов, а не причина тайм-аута.

В 0.12.110 для сетевых операций звонка был введён общий тайм-аут одного HTTP-запроса 15 секунд. Создание делало две попытки и после их неуспеха сразу показывало ошибку. При этом создание ещё не использовало цикл восстановления, доступный последующим этапам звонка. Старый диагностический фильтр не сохранял `InterruptedIOException`, поэтому серверный журнал также терял конкретный тип этого исключения.

## Изменения

- Создание вызова Android использует ограниченный цикл сетевых повторов с тем же бюджетом восстановления, что последующие этапы. Успешный запрос не получает дополнительных задержек; тайм-аут одного запроса остаётся 15 секунд. По окончании бюджета новые повторы не начинаются.
- Один `client_id` создаётся на всё нажатие «Позвонить», включая повторы после потери ответа. Это позволяет серверу вернуть прежний вызов, а не создавать новый на каждой попытке. Завершённый результат повторного запроса не запускает подготовку WebRTC заново.
- До получения идентификатора вызова показывается окно «Подготовка звонка» с состоянием запроса и кнопкой «Отменить». Отмена закрывает окно и отменяет операцию. Микрофон на этом этапе не запускается. Поздно обнаруженный незавершённый вызов освобождается существующим механизмом сверки и очередью завершения.
- В диагностику добавлены `InterruptedIOException`, событие `start_retry`, длительность запроса и безопасное поле `transport_stage`: подготовка авторизации, DNS, соединение, TLS, отправка запроса, ожидание/чтение ответа либо обновление авторизации. Эти этапы снимаются из HTTP-клиента, без сохранения URL, адресов, заголовков, токенов и SDP.

Это исправление обработки временной недоступности, а не подтверждение исправности сети телефона. В старом журнале недостаточно данных, чтобы различить DNS, TLS, обновление авторизации и ожидание ответа. При повторении новая сборка покажет конкретный этап.

Очередь завершения, пауза 429, контроль аудиопакетов, TURN-only, звуки и версия WebRTC 150.7871.01 сохранены. Изменения создания вызова относятся к Android; сервер обновляется для приёма дополнительных диагностических полей.

## Обновление

Из `/root/volna-messenger`, где находятся `.env` и `compose.yaml`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.111 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.111-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Установите **Android 0.12.111 (12111)** на телефон, с которого звоните; для последующих проверок рекомендуется обновить оба телефона. Для сборки только Android замените `sh scripts/build-clients.sh` на `sh scripts/build-android.sh`. Настройки, данные и артефакты сохраняются, перед обновлением создаётся резервная копия. Windows-builder требует 4 ГБ свободного места.

## Проверки

Прошли 292 Node-теста и 254 Android-теста. Собраны Web, Windows renderer и проверочный APK 0.12.111 (12111).

Настоящий HTTP-тест Android возвращает две временные ошибки и затем успешный ответ: все три запроса используют одинаковый `client_id`. Проверяются сохранение типа тайм-аута и этапа запроса, окно ожидания/отмены, существующие пределы повторов и отмена корутины, серверная идемпотентность и фильтрация диагностических полей. Собираются APK, Web и Windows renderer.

Сеть телефона Samsung в среде сборки недоступна. Если ошибка повторится, пришлите новую ссылку `/calllog`: по `transport_stage`, типу исключения и времени повтора можно будет определить, какой участок требует следующего исправления.
