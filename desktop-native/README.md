# Волна Native Desktop 0.1.0

Отдельный экспериментальный Windows-клиент Qt/C++ для API Волны. Нативные экраны входа, список чатов, история, редактор сообщений, меню, файлы и трей. Звонки, видео и голосовые используют действующий WebRTC-механизм Волны в изолированном Qt WebEngine. Приложение не требует установленного Telegram и не подключается к его серверам.

Это начало переноса, а не полный форк интерфейса Telegram Desktop: из закреплённого tdesktop v6.3.3 используются оригинальные палитры, из его зависимостей — QR-генератор. Код MTProto, Telegram API ID, аккаунты Telegram, его логотип и установщик не используются. Состав и SHA-256 исходных файлов записаны в `third_party/sources.json`. Новые исходники клиента распространяются по GPL-3.0-or-later; QR-код — MIT, Qt — по открытым лицензиям в `third_party/qt`.

## Возможности первой сборки

- Вход QR с подтверждением на Android или номер + код в служебном чате Волны; регистрация компьютером не выполняется.
- Список личных чатов, существующих групп, каналов и тем; фильтр чатов, поиск собеседника и новый личный чат.
- История с загрузкой предыдущих страниц; входящие сообщения по SSE с переподключением; отправка с постоянным `client_id` при повторе после потери ответа.
- Редактирование своих сообщений, копирование текста и удаление с подтверждением. Сервер применяет права каналов и служебных чатов.
- Загрузка и скачивание файлов до 20 МБ, просмотр изображений, воспроизведение аудио/видео, запись голосового сообщения.
- Исходящие/входящие аудио- и видеозвонки, микрофон, камера, выбор аудиоустройств, диагностика, TURN и восстановление соединения через существующий модуль Волны.
- День/ночь на палитрах Telegram Desktop, трей, уведомления, статус активности только при видимом активном окне.
- Windows DPAPI, атомарная запись сеанса, один процесс на профиль; отдельное от Electron хранилище. На Linux проверочная сборка хранит сеанс только в памяти.

Пока отсутствуют управление группами/темами, полный редактор профиля, несколько аккаунтов, реакции/стикеры, расписание отправки, автообновление нативного установщика и системный выбор экрана для демонстрации. Захват экрана намеренно не разрешается без выбора пользователя. Действующий клиент Волны остаётся установленным отдельно; новая программа не подменяет его обновления или протокол ссылок. Эта версия не объявляется полной заменой действующего клиента.

## Сборка Windows x64

Нужны Windows 10/11 x64, Visual Studio 2022 C++ Desktop, CMake 3.25+, Ninja, Inno Setup 6 и Qt **6.10.2 msvc2022_64** с WebEngine, WebChannel, Positioning и Declarative. Выполните из Developer PowerShell:

```powershell
$env:QT_ROOT_DIR = 'C:\Qt\6.10.2\msvc2022_64'
./desktop-native/scripts/build-windows.ps1
```

Скрипт собирает приложение, запускает C++-тесты, кладёт Qt DLL/плагины/WebEngineProcess, лицензии, portable ZIP и отдельный установщик в `build-native`. Работает workflow **Volna Native Desktop**, артефакт содержит установщик, portable ZIP и соответствующий исходный код. Предварительный выпуск: https://github.com/andluk87/volna/releases/tag/native-v0.1.0 (установщик пока без цифровой подписи). Версия нативной ветки — 0.1.0; текущая версия остальных клиентов не меняется.

Звонкам и голосовым нужна новая страница `native-call.html` на сервере: обычный `npm --prefix client ci && npm --prefix client run build` включает её в `client/dist`; обновите Web штатным способом. До обновления Web нативные чаты работают, а клиент сообщает, что модуль звонков недоступен. API авторизации совместим с сервером Волны 0.12.112.

## Проверка Linux / разработка

Qt 6.10.2 Widgets, Network, WebEngineWidgets, WebChannel, Test; CMake, компилятор C++20:

```sh
cmake -S desktop-native -B build-native -DCMAKE_PREFIX_PATH=/path/to/Qt/gcc_64
cmake --build build-native --parallel 3
QT_QPA_PLATFORM=offscreen ctest --test-dir build-native --output-on-failure
./build-native/VolnaDesktop
```

По умолчанию сервер `https://volna.lknet.ru`. Для локального тестового сервера разрешён `--server http://127.0.0.1:PORT`; в других случаях требуется HTTPS. Пароль, токен и параметры в URL сервера запрещены. Перенаправления API не выполняются. Мост звонков существует только на странице `/native-call.html` того же origin, не выдаёт refresh token и использует единый нативный механизм обновления сеанса. Браузерный профиль непостоянный; токены не передаются в URL, localStorage или JS-файле.

Для интеграционных проверок сначала соберите `client/dist`, затем задайте `VOLNA_NATIVE_FIXTURE_SCRIPT` абсолютным путём к `tests/native-desktop-fixture.mjs` и запустите `volna_native_integration`. Проверка реальных RTP/видео выполняется с локальным coturn на 127.0.0.1:3478, тестовым REST-secret `volna-native-local-test-only` и `VOLNA_NATIVE_TURN_TEST=1`; для Chromium используются тестовые аудио/видеоисточники. Этот секрет относится только к локальным тестам и не должен использоваться в боевом TURN. Контроль исходных файлов: `python3 desktop-native/scripts/verify-sources.py`.
