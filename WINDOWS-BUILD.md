# Windows 11 x64 · Волна 0.11.41

Клиент содержит локально встроенный интерфейс Волны на Electron. Он поддерживает звонки, выбор окна/монитора для демонстрации, системные уведомления, трей, Telegram-вход через системный браузер и обновления внутри приложения.

## Сборка в Docker и публикация

Сохраните существующий `.env`; в нём требуется `VITE_API_URL=https://volna.lknet.ru` (либо ваш HTTPS-домен). Из корня действующего проекта:

```sh
sh scripts/build-windows.sh
```

Для Android, Windows и одного обновления сервера/Web:

```sh
sh scripts/build-clients.sh
```

При проблемах DNS внутри Docker на Linux VPS используйте `VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh`: режим поддерживается в сборщиках Android/Windows и при сборке сервисов. Полная инструкция выпуска: [UPDATE-0.11.41.md](UPDATE-0.11.41.md).

Скрипт проверяет версию, PE-формат, SHA-512/размер и blockmap перед публикацией. При ошибке сборки или проверки обновление не продолжается. Для первоначального включения TURN поддерживается `sh scripts/build-clients.sh --enable-calls`; если звонки уже работают, этот флаг не нужен.

После успешной публикации:

- Первый установщик: `https://volna.lknet.ru/download/volna-windows.exe`.
- Метаданные: `https://volna.lknet.ru/download/windows/latest.yml`.
- Версионные EXE и blockmap: `/download/windows/Volna-Setup-0.11.41.exe` и соответствующий `.blockmap`.

На странице входа есть кнопки Android и Windows. Нельзя получить файлы по этим адресам до сборки/публикации на VPS. Nginx отдаёт реальные файлы и HTTP Range; метаданные отдаются без кеширования, отсутствующий EXE возвращает 404.

## Если сборка завершилась с `no space left on device`

Ошибка означает нехватку дискового пространства при распаковке Docker-слоя. С версии 0.11.36 сборщик использует `node:24-bookworm-slim` без Wine и проверяет место до загрузки образа. Фактический размер Docker-образа здесь не измерялся.

На VPS освободите старый Windows-образ, если он существует, и неиспользуемый кеш Docker-сборки:

```sh
if docker image inspect volna-windows-builder:latest >/dev/null 2>&1; then
  docker image rm volna-windows-builder:latest
fi
docker builder prune -af
df -h
```

Удаляется только указанный образ и неиспользуемый кеш сборки Docker. Сохраните `.env`, `artifacts` и тома Docker: там база, вложения, модели, ключ APK и кеши зависимостей. Скрипт сам не очищает их и не запускает prune. Следующие Docker-сборки могут повторно скачать удалённые базовые слои; npm/Gradle/Electron-кеши в `artifacts` сохраняются.

По умолчанию требуется 4096 MiB свободного места на каждой доступной локальной файловой системе проекта/Docker/containerd. Если после очистки места всё ещё недостаточно, увеличьте диск. Для сознательного изменения порога: `WINDOWS_BUILD_MIN_FREE_MB=2048 sh scripts/build-windows.sh` (минимальное допустимое значение 512). Это порог проверки, а не гарантированный верхний предел использования диска.

Распакуйте архив 0.11.41 поверх проекта и выполните `sh scripts/build-windows.sh`, чтобы повторить только упавшую Windows-часть и обновить сервер/Web. Если Android уже собран в предыдущем запуске, его не требуется собирать ради этого исправления. Для обновления сразу обоих клиентов используйте `sh scripts/build-clients.sh`.

## Как работает сборка без Wine

`resedit` записывает значки и сведения о версии в Windows PE в отдельном Node-процессе, чтобы его буферы освобождались до упаковки. В Docker используется уровень сжатия 7-Zip 5 вместо максимального; ограничений CPU контейнера нет. Закреплённый `electron-builder 26.0.12` содержит `UninstallerReader`, который извлекает NSIS-деинсталлятор без запуска Windows EXE. Адаптер выбирает этот путь только на время соответствующей операции в Linux; исходники зависимостей в постоянном кеше не переписываются. Если версия или реализация builder изменится, адаптер останавливает сборку для проверки совместимости. NSIS-установщик, приложение, контрольные суммы, blockmap и generic update feed сохраняют прежний формат. Выпуск пока не подписан Authenticode.

## Использование и встроенные обновления

Установите приложение один раз. Крестик окна оставляет его в трее для уведомлений и звонков. Полный выход — через меню трея → «Выйти».

Проверка обновлений: после запуска, каждые шесть часов и меню трея → «Проверить обновления». Нажмите «Обновить»: клиент скачает и проверит установщик, затем установит его и перезапустится. Повторное ручное скачивание с сайта не требуется; сессия и настройки сохраняются. Во время звонка установка ждёт окончания разговора и вашего нажатия «Перезапустить». При ошибке скачивания установка не запускается.

Telegram открывается в системном браузере; callback `volna://auth` возвращает в клиент. Сервер должен разрешать origin `app://volna`, входящий в стандартные настройки проекта. Установщик пока не подписан сертификатом Authenticode; Windows может показать неизвестного издателя при первой установке.

## Кеш сборки

| Каталог | Содержимое |
| --- | --- |
| `artifacts/windows-npm` | Загруженные npm-пакеты |
| `artifacts/windows-node-modules` | Зависимости; переустанавливаются при смене lock-файла/Node |
| `artifacts/windows-electron` | Архив Electron |
| `artifacts/windows-builder` | NSIS и упаковочные инструменты |
| `artifacts/windows-release/<версия>` | EXE, blockmap, feed и проверенные сведения о выпуске |

Сохраняйте весь `artifacts` и ранее опубликованные файлы `client/public/download/windows`. Старые blockmap нужны дифференциальному обновлению. Каталог скачиваний исключён из самого Windows-приложения и образа его сборщика.

## Проверка после установки

Проверьте вход/Telegram, сохранение сессии, уведомления с закрытым окном, звонок Windows ↔ Android/Web, гудок до ответа, микрофон и выбор экрана. Для проверки обновления установите предыдущую версию, опубликуйте следующую и обновите из приложения; проверьте сохранение сессии и отсутствие перезапуска во время звонка.
