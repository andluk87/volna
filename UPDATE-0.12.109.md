# Волна 0.12.109 — лимиты запросов и восстановление звонков

В журнале 0.12.108 обнаружены ответы HTTP 429 на опрос состояния и историю звонков. Запросы всех устройств, включая фоновый опрос и диагностику, расходовали общий лимит аккаунта 240 запросов в минуту. Из-за этого начинали отказывать и обычные действия в переписке.

Опрос состояния, конфигурация TURN, диагностика и команды согласования теперь имеют отдельные ограниченные бюджеты. Опрос разделён по авторизованной сессии и идентификатору устройства/окна; дополнительно ограничена суммарная нагрузка сессии. Общий лимит переписки сохранён. Ограничения диагностики, проверка участников звонка и владения устройством остаются в силе. Это исправление работает после обновления сервера, в том числе для клиентов 0.12.108.

## Соединение и восстановление

В четырёх Android-вызовах из нового журнала первый ответ содержал ноль relay-кандидатов при состоянии сбора `complete`. Сервер запускал повторное согласование; принятие → соединение занимало до 8,8 секунды. Вызов с первым непустым ответом Windows соединился примерно за 3,1 секунды.

- Состояние `complete` без relay больше не разрешает немедленно отправить пустой SDP. Клиенты ждут появления кандидатов в пределах существующего десятисекундного срока. Непустой завершённый сбор и стабилизировавшийся relay отправляются без лишнего ожидания.
- У принимающего Android-клиента отключён предварительный пул ICE-кандидатов, который в этой схеме мог завершиться до установки удалённого SDP. Прогрев конфигурации и фабрики WebRTC сохранён; получатель собирает кандидаты после согласования SDP. У инициатора пул сохранён.
- После первого соединения звук подключения больше не включается при восстановлении: голос и гудки не накладываются друг на друга. До первого соединения звуки вызова сохранены.
- Android сверяет фактическое состояние WebRTC после применения актуального поколения ICE. Уже восстановившееся соединение возвращается в «Разговор», даже если WebRTC не прислал повторное событие `connected`.
- Изменение только признака проверки Интернета на том же Android-маршруте больше не запускает лишнее ICE-восстановление. Смена самой сети отслеживается.

TURN-only, трёхминутный предел восстановления и завершение пользователем сохранены. Фактическую скорость и переключение Wi-Fi ↔ мобильная сеть нужно подтвердить новым вызовом на телефонах; журнал доказывает причину повторного согласования, но не измеряет результат новой сборки.

## Windows

Убран нижний внутриприкладной баннер «имя отправителя: текст», показанный на скриншоте. Обычные уведомления Windows и короткие подтверждения действий, например «Скопировано», сохранены. В Web предпросмотр сообщения не меняется.

## Обновление

Из `/root/volna-messenger`, где находятся `.env` и `compose.yaml`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.109 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.109-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Установите **Android 0.12.109 (12109) на оба телефона**, обновите Windows и перезагрузите Web после публикации. Если нужен только Android, замените `sh scripts/build-clients.sh` на `sh scripts/build-android.sh`. Команда делает резервную копию и сохраняет настройки, данные и артефакты. Windows-builder требует 4 ГБ свободного места.

Для быстрого устранения 429 сначала можно обновить только сервер: в той же команде замените последний `VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh` на `docker build --network=host -f docker/server.Dockerfile -t volna-server . && docker compose up -d --no-deps --no-build server`. Изменения звука и соединения требуют новых клиентов.

## Проверки

Прошли 283 Node-теста и 247 Android-тестов. Собраны Web, Windows renderer и проверочный APK 0.12.109 (12109). Браузерные проверки выполнены на Chromium.

Проверены три сессии одного аккаунта с параллельным опросом, независимость окон одной сессии, сохранение доступа к переписке и конфигурации после превышения лимита опроса, существующие ограничения диагностики. Регрессия пустого ответа проверяется сценарием `complete` без кандидатов, после которого появляются relay. Проверены отсутствие звука восстановления поверх установленного разговора, настройка пула Android, интерфейсы Web/Windows и сборки клиентов.

После обновления проверьте первый вызов и переключение сети во время разговора. Ссылка из меню бота `/calllog` позволит сравнить первый ответ, число ICE-восстановлений и время принятие → соединение.
