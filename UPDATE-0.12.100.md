# Волна 0.12.100 — постоянный журнал звонков

Журнал включён постоянно, без переключателей. В стандартном Docker-развёртывании файл находится в контейнере `server`:

```text
/data/logs/volna-calls.log
```

Каталог хранится в существующем постоянном volume `chat-data`; пересоздание контейнера не удаляет записи. При запуске вне Docker журнал лежит в `logs/` рядом с базой `DB_PATH`.

## Ротация и архивы

Лимит активного файла — **1 МиБ (1 048 576 байт)**. Когда очередная целая запись перестаёт помещаться, файл архивируется, затем запись продолжается в пустом `volna-calls.log`. На точной границе также выполняется ротация. Это сохраняет целые JSON-строки и не позволяет активному журналу расти сверх лимита. Имя архива содержит назначение журнала, дату/время UTC, PID и номер:

```text
volna-calls_2026-11-02_12-34-56.789Z_pid123_000001.log.tar.gz
```

Внутри — файл `volna-calls.log`. Архив сначала полностью записывается и закрывается, затем очищается активный файл. Архивы автоматически не удаляются, чтобы сохранить собранные данные. Запись продолжается после перезапуска. Ошибка диска/прав выводит предупреждение `[calls-log]` в обычные логи сервера, не прерывая звонок и не стирая исходный журнал. Каталог создаётся с правами 0700, файлы — 0600.

## Какие данные собираются

Сервер фиксирует создание и завершение звонка, ID участников/устройств, принятие, offer/answer как события без их содержимого, подтверждение входящего, Web Push, конфигурацию наличия TURN, ошибки запросов, восстановление ICE и конкретную причину тайм-аута. Записываются также незавершённые звонки, найденные после перезапуска сервера.

Обновлённые Android, Web и Windows автоматически отправляют этап подключения, тип ошибки, состояния ICE/WebRTC, количество кандидатов по типам и транспортам, код ошибки ICE. Каждые 15 секунд во время настройки медиасоединения и разговора собираются счётчики отправленных/полученных байтов и пакетов, потери, RTT и тип выбранного кандидата. У отчётов есть версия клиента, платформа, ID звонка и время клиента; сервер добавляет своё время UTC. Нужен доступ клиента к API: при полном отсутствии сети его отчёт может не попасть на сервер, но сервер фиксирует отсутствие heartbeat и тайм-аут.

Пароли TURN, токены авторизации, SMS-коды, имена/телефоны, полные SDP, адреса ICE-кандидатов, аудио и видео в этот файл не записываются. Поля клиентских отчётов ограничены списком допустимых значений, доступ разрешён только участникам своего звонка. Запись диагностики не влияет на успешность звонка. Существующий TURN-only режим сохранён.

Примеры причин завершения:

| Причина | Что проверить |
| --- | --- |
| `offer_timeout` | Подготовка микрофона/WebRTC и сбор relay-кандидатов на исходящем устройстве |
| `ring_timeout` | Дошёл ли вызов до второго устройства и был ли принят |
| `media_connect_timeout` | Обмен согласован, но медиаканал не подтверждён; искать ICE/relay/пакеты |
| `caller_heartbeat_timeout` / `callee_heartbeat_timeout` | Потеря доступа соответствующего клиента к API или остановка приложения |
| `ice_restart_timeout` | Восстановление медиаканала после смены/потери сети |

## Смотреть и забрать журнал

Из папки проекта смотреть новые записи:

```sh
docker compose exec -T server tail -F /data/logs/volna-calls.log
```

Забрать активный журнал и все архивы в отдельную папку на хосте:

```sh
docker compose cp server:/data/logs "./volna-call-logs-$(date -u +%Y%m%d-%H%M%S)"
```

Архив читается обычной командой `tar -xOzf имя-архива.log.tar.gz`. После неудачного звонка сохраните журнал и архивы и укажите примерное время попытки — события связываются по `call_id`. Сырые логи coturn остаются в `docker compose --profile calls logs turn`; данный файл собирает журнал приложения и безопасные отчёты клиентов.

## Обновление одной вставкой

Из существующей папки проекта с `.env`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.100 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.100-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; python3 scripts/improve-transcription.py; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

После обновления сервера уже собирается серверная часть. Для состояний WebRTC/ICE обновите Android и Windows до 0.12.100, Web перезагрузите. На вашем сервере обновление автоматически не выполнялось. Проверочные сборки этой среды с `example.invalid` не предназначены для установки вместо сборок с вашим адресом API.

## Проверки

Прошли 257 Node-тестов и 229 Android-тестов; собраны Web, Windows renderer и APK 12100. Проверены настоящий tar.gz через системный `tar`, ротация на 1 МиБ, порядок и сохранность тысяч записей, продолжение после перезапуска, сбои архивирования/записи и права файлов. API-тесты проверяют этапы звонка, тайм-ауты, перезапуск, разрешения диагностики, лимиты отчётов и отсутствие токенов/SDP/телефонов в журнале. Web/Windows проверяются в Chromium, Android — сборкой и тестами сводок ICE/статистики. Физические телефоны и сеть вашего TURN здесь недоступны; локальный тест реального ICE restart пропущен, поскольку облачный Chromium не выдаёт ICE-кандидаты.
