# VLN 0.12.78 — Windows: исправление повторного QR после простоя

Обнаружена и воспроизведена гонка авторизации. Если несколько запросов со старым часовым ключом возвращали `401` в разное время, поздний ответ мог вызвать новое обновление уже действующего ключа. Ранее повторённый запрос тогда снова получал `401`, и интерфейс удалял сохранённый аккаунт.

Теперь запоздавший отказ повторяется с текущим ключом без лишней ротации; IPC получает ключ отклонённого запроса. Общая задача обновления корректно освобождается, сетевой сбой остаётся ошибкой подключения. Повторные смены обрабатываются ограниченным циклом без ложного выхода. Настоящий отзыв устройства по-прежнему завершает вход.

Серверный журнал с серией refresh перед QR согласуется с этим сценарием, но не содержит идентификатора устройства для каждого события и не доказывает единственную причину всех прошлых сбросов.

Из прежней папки сервера с `compose.yaml` и существующим `.env`, одной вставкой:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.78 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.78-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; sh scripts/build-clients.sh )
```

Команда создаёт резервную копию, сохраняет прежние исходники Android в `backups/`, загружает тег `v0.12.78` и запускает общий сборщик. `.env`, база, аккаунты, переписки и ключ подписи Android сохраняются.

После сборки откройте в VLN `Настройки → Обновления → Проверить обновления` и подтвердите установку поверх прежней версии. Обновите Windows поверх прежней версии и перезагрузите Web через `Ctrl+F5`.

После сборки установите **Windows 0.12.78** поверх старой версии. Если экран уже просит QR, понадобится один вход с телефона: удалённые старым клиентом локальные данные нельзя восстановить автоматически. Одна пересборка сервера не обновляет установленный Windows EXE.

Проверка: оставьте клиент работать дольше часа, затем разверните окно, откройте чаты и проверьте второе окно чата. Ожидается сохранение входа. Временное отсутствие сети должно давать повтор подключения, а не новый QR. Явный отзыв Windows-устройства с телефона по-прежнему требует повторного входа.

## Журнал для повторного случая

- Щёлкните правой кнопкой значок VLN в трее → «Журнал авторизации». Работает и на экране QR.
- Вошедший пользователь также может открыть «Настройки → Обновления → Открыть журнал авторизации».
- Папка: `%APPDATA%\Volna\logs`; файлы `session.log` и `session.previous.log`. До ~256 КиБ на файл плюс одна запись; только время UTC, версия, тип события, ID аккаунта, код ответа и длительность. Токены, переписка, пароли, URL и тексты исключений не записываются.

Проверено: 210 Node-тестов, включая сценарии на реальном API и хранилище сеансов; браузерные проверки сохранения входа, перезапуска и отзыва; React render-тесты и production-сборки Web/Windows. Собран Android APK с тем же номером релиза; нативная авторизация Android не менялась. Проверка установленного EXE и DPAPI на физическом Windows-ПК здесь не выполнялась.
