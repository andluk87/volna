# ТЕХНИЧЕСКОЕ ЗАДАНИЕ 2.0
## Максимально точное воспроизведение Telegram Web K

**Проект:** Telegram-style Web Client

**Главный референс:** https://web.telegram.org/k/

**Исходный код для изучения:** https://github.com/TelegramOrg/Telegram-web-k

**Основная цель:** Создать визуально максимально близкий к Telegram Web K веб-клиент, в котором совпадают не только основные блоки, но и пропорции, типографика, отступы, скругления, иконки, расположение сообщений, анимации и поведение элементов.

**Приоритет разработки:**

1. Визуальное соответствие оригиналу.
2. Геометрия и адаптивность.
3. Корректные интерактивные состояния.
4. Реализация основных функций мессенджера.
5. Производительность и качество кода.

---

# 1. Основное требование

Разработать веб-интерфейс, который при первом взгляде воспринимается как Telegram Web K.

Это означает, что нельзя ограничиться:

- Белой панелью слева.
- Голубыми кнопками.
- Круглыми аватарами.
- Простыми пузырьками сообщений.
- Стандартным полем ввода.
- Типовым шаблоном React-мессенджера.

Необходимо воспроизвести конкретную дизайн-систему Telegram Web K.

**Критически важно:** не улучшать и не переосмысливать оригинальный дизайн. Если Telegram использует определённые размеры, цвета или особенности компоновки, их нужно повторять, даже если разработчику кажется, что другой вариант выглядел бы современнее.

Запрещается произвольно добавлять:
- Крупные логотипы в боковую панель.
- Градиенты в интерфейс.
- Большие закруглённые карточки вокруг каждого чата.
- Толстые рамки.
- Лишние тени.
- Большие расстояния между сообщениями.
- Чрезмерно объёмные кнопки.
- Несуществующие элементы навигации.

Внешний вид должен определяться референсом, а не личными предпочтениями разработчика.

---

# 2. Эталон для разработки

Основным референсом выбрать только **Telegram Web K**.

Не смешивать его с:
- Telegram Web A.
- Telegram Desktop.
- Telegram для Android.
- Telegram для iOS.
- Сторонними концептами из Dribbble.
- Готовыми шаблонами мессенджеров.

## 2.1. Подготовка референсов

До разработки необходимо получить скриншоты оригинального Telegram Web K.

Обязательные состояния:

1. Светлая тема, список чатов и открытая переписка.
2. Тёмная тема, тот же список и та же переписка.
3. Чат без выбранной переписки.
4. Диалог с короткими и длинными сообщениями.
5. Группа с несколькими участниками.
6. Переписка с изображениями и файлами.
7. Открытое главное меню.
8. Открытый профиль.
9. Панель настроек.
10. Поиск.
11. Контекстное меню.
12. Панель эмодзи.
13. Мобильный интерфейс.

Референсы сохранить в проекте в каталоге `design/reference/`.

У каждого скриншота зафиксировать:
- Размер viewport.
- Масштаб браузера.
- Тему.
- Состояние интерфейса.
- Дату получения.
- Версию или commit исходного проекта, если используется исходный код.

Для сравнения использовать одинаковые тестовые данные и состояния. Личные данные и сообщения реального аккаунта в тестовых материалах не использовать.

# 3. Базовая геометрия приложения

Telegram Web K должен заполнять доступную область браузера.

Приложение не должно выглядеть как сайт, помещённый в большую центральную карточку.

При этом отдельные панели Telegram могут иметь внешние отступы и собственные скругления — их необходимо воспроизводить по эталону.

## 3.1. Рабочая структура

Основные элементы:

```text
Application
│
├── LeftColumn
│   ├── SidebarHeader
│   │   ├── MenuButton
│   │   └── SearchInput
│   │
│   ├── ChatFolders
│   └── ChatList
│       └── ChatListItem
│
├── MiddleColumn
│   └── Chat
│       ├── ChatTopbar
│       ├── PinnedMessage
│       ├── MessagesViewport
│       │   └── MessagesContent
│       └── MessageComposer
│
├── RightColumn
│   └── Profile / ChatInfo
│
└── OverlayLayer
    ├── DropdownMenu
    ├── ContextMenu
    ├── EmojiPicker
    ├── Modal
    └── MediaViewer
```

Панели должны иметь независимую прокрутку и управляться общим layout-контейнером.

## 3.2. Ширина левой панели

Для базового десктопного режима принять стартовую ширину 360 px.

Предусмотреть:
- Адаптацию ширины к размеру экрана.
- Максимальную ширину согласно выбранной версии референса.
- Состояние свёрнутой панели, если оно есть в эталонной версии.
- Корректную работу при открытой правой панели.

Не задавать ширину как 30% экрана.

Левая панель Telegram не должна становиться огромной на широком мониторе.

**Важное правило:** ширина боковой панели должна определяться дизайн-токенами и правилами responsive layout, а не случайными значениями в разных компонентах.

## 3.3. Центральная область

Центральная область занимает оставшееся пространство, но сами сообщения не растягиваются произвольно от одного края экрана до другого.

Обязательно разделить:

**MessagesViewport** — область прокрутки, занимающая доступную центральную панель.

**MessagesContent** — внутренняя область с ограниченной шириной, внутри которой позиционируются сообщения.

На широком мониторе MessagesContent должен центрироваться относительно рабочей области переписки.

Тот же принцип применять к шапке переписки и панели ввода там, где это предусмотрено референсом.

При открытии правой панели центрирование пересчитывается.

Не использовать примитивную модель `flex: 1` для всех внутренних элементов без ограничений ширины.

# 4. Левая панель

## 4.1. Внешний вид

Левая панель должна иметь:
- Ровную основную поверхность.
- Правильные внешние отступы относительно приложения.
- Скругления только в тех местах, где они есть в эталоне.
- Собственную область прокрутки.
- Отсутствие толстых разделителей между чатами.

В светлой теме поверхность преимущественно белая.

В тёмной теме — тёмная нейтральная поверхность, отличающаяся от фона переписки.

## 4.2. Верхняя строка

Сверху расположить:
- Кнопку меню.
- Поле поиска.
- Предусмотренные референсом дополнительные элементы.

Высоту, вертикальное положение и отступы верхней строки взять непосредственно из оригинала.

Важна оптическая центровка иконок. Недостаточно просто применить `align-items: center`, если визуально кнопки оказываются выше или ниже эталона.

## 4.3. Кнопка меню

Кнопка должна содержать характерную для Telegram иконку меню.

Не использовать случайный набор иконок, похожих на Telegram.

Предпочтительно использовать SVG-геометрию, соответствующую референсу.

Обязательные состояния:
- Default.
- Hover.
- Active.
- Focus-visible.
- Открытое меню.

Подсветка должна быть умеренной, без агрессивных цветовых эффектов.

## 4.4. Поиск

Поле поиска оформить в виде горизонтальной капсулы со скруглёнными краями.

Внутри:
- Значок лупы.
- Placeholder.
- Текст пользователя при вводе.
- Кнопка очистки при наличии запроса.

Требования:
- Не делать поле слишком высоким.
- Не использовать толстую обводку.
- Сохранять правильные внутренние отступы.
- Синхронизировать положение текста и иконки.
- Анимировать переход между обычным и активным состоянием.

При начале поиска список чатов заменяется поисковым представлением, соответствующим оригинальной навигации Web K.

## 4.5. Папки чатов

Папки должны выглядеть как часть интерфейса, а не как набор отдельных кнопок.

Использовать:
- Горизонтальный ряд текстовых вкладок.
- Акцентную подсветку выбранной папки.
- Индикатор активного состояния.
- Правильную высоту строки.
- Горизонтальную прокрутку при необходимости.

Не делать вкладки большими серыми или голубыми pill-кнопками, если в выбранном эталонном состоянии Telegram использует нижнее подчёркивание.

Если папки не настроены, панель вкладок должна отсутствовать.

---

# 5. Список чатов — критически важный компонент

Именно список чатов должен быть реализован особенно точно.

Ошибки в плотности списка, аватарах и типографике сразу делают приложение непохожим на Telegram.

## 5.1. Размеры

Для крупных строк списка использовать базовый ориентир — минимальная высота 72 px.

Не добавлять большие вертикальные отступы сверх эталона.

В пределах одного экрана должно помещаться приблизительно такое же количество строк, как в оригинале.

Каждый элемент содержит:
- Аватар.
- Название.
- Время.
- Превью последнего сообщения.
- Счётчики и индикаторы.

## 5.2. Аватары

Для стандартного крупного списка взять ориентир 54 px, затем откалибровать по референсу.

Форма — строго круглая.

Изображения должны:
- Заполнять круг без деформации.
- Использовать `object-fit: cover`.
- Сохранять качество на Retina-экранах.
- Не иметь случайных рамок.

Если изображения нет, отображать цветной аватар с инициалами.

Цвета таких аватаров использовать из согласованной Telegram-подобной палитры, а не генерировать случайные RGB-значения.

## 5.3. Текст названия

Название располагается справа от аватара, в верхней части текстового блока.

Особенности:
- Компактная высота строки.
- Среднее или полужирное начертание.
- Обрезка многоточием.
- Правильный промежуток до времени.
- Поддержка значков верификации и других статусов.

Не использовать слишком жирный шрифт.

## 5.4. Превью сообщения

Вторая строка должна иметь меньшую визуальную значимость.

Цвет — вторичный текст.

Высота — строго контролируемая.

Длинный текст обрезается.

Если последнее сообщение отправлено самим пользователем, может отображаться префикс автора или статус отправки.

Для типов медиа использовать соответствующие обозначения.

## 5.5. Время и счётчик

Время располагать в правом верхнем участке строки.

Счётчик непрочитанных сообщений:
- Небольшой.
- Круглый или капсулообразный.
- С насыщенной заливкой.
- С контрастным текстом.
- Выравнен по правому краю.

Счётчик не должен растягивать строку или сдвигать название.

При отключённых уведомлениях применять соответствующий приглушённый стиль.

## 5.6. Активный чат

Выделение активного чата должно соответствовать Web K.

Не использовать универсальную голубую карточку без проверки.

Необходимо воспроизвести:
- Фон выделения.
- Радиус строки.
- Цвет названия.
- Цвет превью.
- Цвет счётчиков.
- Взаимодействие с hover.

Выбранная строка должна оставаться активной после перемещения курсора.

# 6. Шапка переписки

Шапка не должна выглядеть как обычный `header` сайта.

Необходимо воспроизвести её фактическую форму, размер, фон и положение в Web K.

## 6.1. Компоновка

Слева:
- Аватар, если отображается в текущем состоянии.
- Имя пользователя или название группы.
- Статус.

Справа:
- Поиск.
- Другие доступные действия.
- Меню с тремя точками.

Не добавлять постоянно видимые кнопки, которых нет в оригинальном референсе.

## 6.2. Типографика

Имя — основной текст средней плотности.

Статус — второстепенный текст меньшего размера.

Статус «в сети» может использовать акцентный цвет.

Между именем и статусом должен быть маленький, точно подобранный промежуток.

## 6.3. Геометрия

При построении шапки учитывать:
- Внутреннюю высоту.
- Внешние отступы.
- Радиусы углов.
- Горизонтальные поля.
- Размер кнопок.
- Ограничение ширины рабочего содержимого.

Не растягивать все элементы от левого до правого края монитора, если эталон ограничивает их положение.

# 7. Область сообщений

## 7.1. Фон

Фон переписки — один из самых узнаваемых элементов Telegram.

Использовать подходящий оригинальному Web K декоративный фон для выбранной темы.

Требования:
- Правильный масштаб рисунка.
- Правильная прозрачность.
- Правильная цветовая гамма.
- Отсутствие сильного контраста.
- Корректное позиционирование при изменении размеров окна.

Не заменять декоративные обои обычным серым фоном, если в эталоне присутствует узор.

Не использовать произвольную фотографию природы или абстрактный градиент.

Если оригинальный графический ресурс недоступен для легального использования, создать собственный близкий по визуальной плотности и стилю вариант без копирования защищённых материалов.

## 7.2. Расположение сообщений

Входящие — слева.

Исходящие — справа.

Сообщения ограничиваются общей шириной MessagesContent.

Важны не только направления выравнивания, но и точные горизонтальные позиции относительно центральной области.

На большом мониторе входящие сообщения не должны прилипать непосредственно к границе боковой панели.

## 7.3. Форма пузырьков

Не использовать стандартный CSS-шаблон с огромными радиусами `20px` и отступами `16px`.

Telegram использует более компактную и сложную форму пузырьков.

Необходимо реализовать:
- Скругления верхних углов.
- Изменяемую форму нижних углов.
- Характерный хвостик при необходимости.
- Группировку соседних сообщений.
- Корректную форму сообщений с медиа.

В исходных стилях Web K присутствует система переменных радиусов углов. Воспроизвести её отдельными CSS-токенами или модификаторами.

## 7.4. Размеры пузырьков

Стартовые параметры для калибровки:
- Размер основного текста: около 16 px.
- Межстрочный интервал: приблизительно 1.3–1.4.
- Боковые внутренние отступы: около 10–12 px.
- Вертикальные отступы: минимальные, соответствующие референсу.
- Минимальная ширина содержимого: 56 px.
- Максимальная ширина: рассчитывается относительно ширины рабочей области и типа сообщения.

Точные размеры не считать утверждёнными до визуального сравнения.

## 7.5. Тени

У пузырьков должна быть очень слабая естественная тень, если она присутствует в эталонной теме.

Не применять выраженные тени уровня `shadow-lg` или `shadow-xl`.

Тень должна лишь слегка отделять сообщение от фона.

## 7.6. Время сообщения

Время расположить внутри нижнего участка сообщения.

В Telegram оно часто оказывается на той же строке, что и окончание текста, если доступна ширина.

При нехватке пространства время должно корректно переноситься или занимать отдельную зону, не перекрывая текст.

Не реализовывать время отдельной строкой под каждым сообщением по умолчанию.

Требуется специальная логика расчёта ширины текста и служебной области.

## 7.7. Галочки

Рядом со временем исходящего сообщения отображать статус.

Галочки:
- Небольшие.
- Аккуратно выровненные.
- Выполнены в стиле Telegram.
- Не выглядят как две стандартные иконки из произвольной библиотеки.

## 7.8. Группировка

Последовательные сообщения одного человека объединять визуально.

Для группы сообщений:
- Уменьшать вертикальный зазор.
- Изменять углы при необходимости.
- Не повторять аватар там, где его скрывает оригинал.
- Не создавать большой промежуток после каждого пузырька.

## 7.9. Разделители дат

Разделители дат делать небольшими, полупрозрачными, центрированными относительно контента переписки.

Не превращать их в широкие горизонтальные полосы.

---

# 8. Нижняя панель ввода

Это второй по важности компонент после списка сообщений.

## 8.1. Структура

Панель ввода должна состоять из:
- Основной поверхности редактора.
- Кнопки эмодзи.
- Текстового поля.
- Кнопки вложений.
- Отдельной кнопки отправки или записи, если так предусмотрено эталоном.

Не размещать всё внутри одного прямоугольника с тонкой рамкой.

## 8.2. Геометрия

Панель должна:
- Находиться в нижней части окна чата.
- Иметь правильное ограничение максимальной ширины.
- Выравниваться по центру рабочей области переписки.
- Сохранять предусмотренный референсом нижний отступ.
- Иметь округлую основную поверхность.
- Поддерживать многострочный ввод.

Кнопка отправки может располагаться в отдельном круглом блоке справа от поля.

Следует воспроизвести именно состояние Web K, а не переносить компоновку из Telegram Desktop.

## 8.3. Кнопка отправки

В пустом поле отображается микрофон, если этот режим доступен.

После ввода текста появляется кнопка отправки.

Переход между состояниями должен быть плавным.

Кнопка:
- Круглой формы.
- С корректным акцентным фоном.
- С иконкой правильной формы и размера.
- Без чрезмерной тени.

## 8.4. Редактор

Требования:
- Правильная высота одной строки.
- Вертикальное расширение.
- Корректные переносы.
- Поддержка вставки текста.
- Отдельное отображение режима ответа.
- Отдельное отображение редактирования сообщения.
- Корректная работа при длинном тексте.

Enter — отправка.

Shift + Enter — перевод строки.

# 15. Адаптивная компоновка

Не использовать только один breakpoint 768 px.

В Web K адаптивность включает изменение логики расположения боковой панели, центральной области и профиля.

## 15.1. Широкий desktop

- Боковая панель закреплена.
- Переписка занимает рабочую центральную область.
- Контент переписки центрирован.
- Допускается открытие правой панели.
- Не возникает растянутых на огромную ширину сообщений.

## 15.2. Средняя ширина

- Боковая панель может переходить в плавающий режим.
- Центральная область сохраняет нужную ширину.
- Меняются горизонтальные отступы.
- Правая панель не должна нарушать доступность переписки.

## 15.3. Мобильный экран

- Отображается один основной экран.
- Список чатов и переписка переключаются как отдельные представления.
- В шапке чата появляется кнопка возврата.
- Поле ввода учитывает экранную клавиатуру.
- Меню адаптируются к узкому viewport.
- Используются safe-area отступы.

**Точные breakpoints определить из исходных правил Web K или через замеры эталонного интерфейса.** Нельзя считать универсальные точки 768/1024/1200 гарантированным соответствием оригиналу.

## 18.1. Сравнение скриншотов

Создать снимки оригинала и реализации при одинаковых условиях.

Основные viewport:

- 1920 × 1080.
- 1440 × 900.
- 1366 × 768.

- При необходимости — профиль и меню.

## 18.2. Проверка наложением

Использовать overlay двух скриншотов с прозрачностью 50%.

Разработчик должен видеть отклонения:
- Контуры панелей не совпадают.
- Строки имеют разную высоту.
- Аватары сдвинуты.
- Сообщения имеют другую ширину.
- Поле ввода находится слишком низко.
- Шрифт отличается.
- Цвета заметно расходятся.

Исправлять расхождения до перехода к следующему компоненту.

## 18.3. Автоматическая проверка

Использовать Playwright screenshot tests.

Настроить:
- Фиксированный viewport.
- Одинаковый deviceScaleFactor.
- Фиксированные тестовые данные.
- Стабильное время сообщений.
- Контроль загрузки изображений и шрифтов.
- Отключение недетерминированных анимаций на время снимка.
- Маскирование только действительно динамических элементов.

Для каждого контрольного экрана хранить baseline-скриншот.

Изменения в UI должны проверяться сравнением с baseline.

## 18.4. Допуски

|---|---|

10. Нельзя завершать визуальную разработку без сравнения скриншотов.

# 22. Ограничения и дальнейшая интеграция

Первый этап — самостоятельное веб-приложение с визуально точным интерфейсом Telegram Web K и демонстрационными данными.

Подключение настоящих аккаунтов Telegram, MTProto, синхронизация переписок, авторизация, звонки и полноценная отправка медиа в Telegram не входят в этот этап.

Они требуют отдельной реализации с использованием официально разрешённых API, соблюдением требований безопасности и лицензий.

Если используются фрагменты исходного кода Web K, необходимо учитывать GPL-3.0 и условия распространения производного программного обеспечения.

# 23. Ожидаемый итог

Результат — интерактивный веб-клиент, который максимально близко воспроизводит Telegram Web K.

На контрольном скриншоте с одинаковыми данными интерфейс должен совпадать по:
- Компоновке.
- Пропорциям.
- Типографике.
- Цветам.
- Отступам.
- Иконкам.
- Форме сообщений.
- Фону.
- Расположению ввода.
- Состояниям интерфейса.

**Главное правило проекта: сначала добиться визуального совпадения с Telegram Web K и только затем расширять функциональность.**

Разработчик не должен самостоятельно редизайнить приложение. Все заметные отличия от эталона должны быть либо исправлены, либо документально согласованы как осознанные отклонения.
