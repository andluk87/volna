# Волна 0.12.108 — восстановление звонков, звуки и эмодзи

Во время входящего вызова Android, Web и Windows заранее получают TURN-конфигурацию и создают WebRTC peer. Микрофон и аудиофокус включаются только после принятия. Отмена, смена аккаунта и смена сети освобождают предварительное соединение. Это сокращает работу после нажатия «Принять»; фактическое ускорение нужно измерить на телефонах.

При смене Wi-Fi на мобильную сеть и обратно клиент запускает ICE-восстановление в рамках того же звонка. Временная потеря сети показывает ожидание и повторяет сетевые запросы; предел восстановления — три минуты. Сохраняются идентификатор звонка и начало разговора. Во время входящего вызова сетевой перерыв приостанавливает отсчёт ожидания ответа. После трёх минут без восстановления звонок завершается. Завершение пользователем и принятие на другом устройстве остаются окончательными. Для полного поведения обновите оба клиента и сервер; сервер сохраняет прежние сроки для старых клиентов.

Добавлены оригинальные MP3 Telegram: Android использует мобильные звуки ожидания, подключения и завершения; Web/Windows — Desktop. Занято и ошибка имеют отдельные сигналы. Выбранная пользователем мелодия входящего Android-звонка сохраняется. Источники, контрольные суммы и лицензии: [third-party/telegram-sounds](third-party/telegram-sounds/README.md).

Вместо шестнадцатеричных символов на экране звонка показываются четыре одинаковых у собеседников эмодзи, вычисленные из кода проверки DTLS. При сравнении они должны совпадать. Полный код доступен в подробностях. Android, Web и Windows используют общий порядок эмодзи.

TURN-only сохраняется. Диагностика отмечает предварительную подготовку и потерю/появление сети; SDP, адреса и пароли в неё не добавляются.

## Обновление

Из `/root/volna-messenger`, где находятся `.env` и `compose.yaml`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.108 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.108-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Установите **Android 0.12.108 (12108) на оба телефона**, обновите Windows; Web перезагрузите после публикации. Если нужен только Android, замените `sh scripts/build-clients.sh` на `sh scripts/build-android.sh`. Команда сохраняет настройки и данные, делает резервную копию. Windows-builder требует 4 ГБ свободного места.

## Проверки

Прошли 280 Node-тестов (общий прогон и дополнительный тест повторной смены сети) и 247 Android-тестов. Собраны Web, Windows renderer и проверочный APK 0.12.108 (12108).

Проверены соответствие эмодзи Android и Web, отмена и предел сетевых повторов, сохранение звонка после минуты без сети, повторная смена сети во время восстановления и приостановка входящего вызова. Браузерная проверка с настоящим RTCPeerConnection подтверждает подготовку без микрофона, замену peer после возвращения сети и освобождение при отклонении. Проверены интерфейсы Web/Windows, сборки клиентов и версия APK.

Физическое переключение Wi-Fi ↔ мобильная сеть в среде сборки недоступно. После обновления проверьте его во время вызова и разговора; новый `/calllog` позволит оценить время соединения и восстановления.
