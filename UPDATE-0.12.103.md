# Волна 0.12.103 — подробный журнал звонков и бот диагностики

У Android-завершений теперь обязательна причина. Журнал различает кнопку пользователя, отклонение, команды Android Telecom (`disconnect`, `reject`, `abort`), сброс сессии, ответ сервера об отсутствии звонка, чужое устройство, остановку сервиса, потерю аудиофокуса и тайм-ауты. Причина также передаётся в самой команде `/end` и записывается сервером как `call.end_requested.end_reason`, независимо от очереди телеметрии.

Сохраняются события Telecom, сервиса звонка, Activity, запуска MessagingService, перенастройки сессии с источником вызова, состояния WebRTC/ICE, сводки кандидатов, сетевой транспорт Android (Wi-Fi / мобильная сеть / VPN), доступность сети, модель устройства и версия Android. Каждое клиентское событие содержит идентификатор процесса, последовательный номер, время клиента и монотонное время устройства или вкладки. Счётчики RTP и RTT снимаются каждые 5 секунд. Web/Windows также сообщают причину завершения, сворачивание/возврат окна, скрытие вкладки и завершение дорожки микрофона.

Лог остаётся в `/data/logs/volna-calls.log`; при размере 1 МиБ создаётся именованный `.log.tar.gz`. Android дублирует диагностические события в logcat с тегом `VolnaCallDebug`. Сырые SDP, IP-адреса кандидатов, токены входа, TURN-пароли, содержимое сообщений и разговоров не записываются. Отправка диагностики выполняется без блокировки медиа; при отсутствии сети отдельные события могут не дойти до сервера. Журнал позволяет установить источник сбоя, но это обновление само по себе не объявляет проблему первого звонка исправленной.

## Бот в Волне

В списке чатов администратора **+7 968 141-12-41** автоматически появляется **«Волна — диагностика»**. Используется настроенный номер администратора (`ADMIN_PHONE`, по умолчанию указанный выше). Перезапустите приложение или обновите список чатов после обновления сервера.

- `/calllog` — создать ссылку на журнал на 24 часа (`/logs` или «логи» тоже работают).
- `/revoke` — немедленно отозвать ссылку.
- `/help` — список команд.

Ссылка имеет вид `https://volna.lknet.ru/api/call-debug/<случайный ключ>`. Пришлите её в этот разговор: по ней можно читать актуальный журнал без доступа к вашему аккаунту. Одна ссылка работает и до, и после двух тестовых звонков. Она показывает текущий файл и два последних архива; более старые архивы доступны администратору для скачивания. Создание новой ссылки отменяет предыдущую. Доступ закрывается через 24 часа или по `/revoke`; ссылка сохраняет работоспособность после перезапуска сервера до своего истечения. Получатель ссылки может читать журнал до её отзыва.

Бот выдаёт ссылки только в личном чате настроенного администратора и не выдаёт их в чат с добавленными посторонними участниками. Повторная доставка одной команды не создаёт новую ссылку. Публичный адрес берётся из существующего `CHAT_DOMAIN` в `.env`.

## Просмотр на сайте

В панели администратора на `https://volna.lknet.ru:8998` появился раздел **«Журнал звонков»**: последние 300 записей, обновление, скачивание недавней истории и отдельных файлов, создание/отзыв ссылки. Управление защищено действующим входом по SMS и CSRF. По временной ссылке доступен только текст журнала звонков; SQL-база, пользовательские файлы, сообщения и настройки недоступны. Ключ ссылки хранится в таблице доступа только в виде хеша; ответы не кэшируются.

## Полное обновление одной вставкой

Запустить из `/root/volna-messenger`, где находятся `.env` и `compose.yaml`:

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.103 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; if [ -d android-native/app/src ]; then mkdir -p backups; volna_source_backup=$(mktemp -d "$PWD/backups/android-source-0.12.103-XXXXXXXX"); mv android-native/app/src "$volna_source_backup/src"; fi; tar -xf "$volna_update_dir/source.tar" -C .; VOLNA_BUILD_NETWORK=host sh scripts/build-clients.sh )
```

Команда сохраняет `.env`, постоянные данные, ранее опубликованные клиенты и резервную копию. Сеть хоста используется для обхода ранее выявленной ошибки DNS внутри Docker. Сборка Windows требует не менее 4 ГБ свободного места; исходники и обновлённый сервер не устанавливаются автоматически в этой рабочей среде на ваш хост.

**Установите Android 0.12.103 на оба телефона.** Обновите Windows-клиент до 0.12.103, а в браузере перезагрузите страницу. Затем создайте ссылку через `/calllog`, воспроизведите неудачную и успешную попытки подряд и пришлите ссылку.

## Если сейчас нужен только бот и доступ к существующему журналу

```sh
( set -eu; test -f compose.yaml && test -f .env; volna_update_dir=$(mktemp -d); trap 'rm -rf "$volna_update_dir"' EXIT; git clone --depth 1 --branch v0.12.103 https://github.com/andluk87/volna.git "$volna_update_dir/source"; git -C "$volna_update_dir/source" archive --output="$volna_update_dir/source.tar" HEAD; sh "$volna_update_dir/source/scripts/backup.sh"; tar -xf "$volna_update_dir/source.tar" -C .; docker build --network=host -f docker/server.Dockerfile -t volna-server .; docker compose up -d --no-deps --no-build server )
```

В таком случае бот уже работает в существующих клиентах, но расширенные причины завершения появятся только после установки новых клиентов. Для диагностики текущей проблемы обновление обоих телефонов обязательно.

## Проверки

Прошли 267 Node-тестов и 230 Android-тестов. Собраны Web, Windows renderer и Android APK; проверена версия 0.12.103 (12103).

Проверяются причина `/end`, фильтрация секретов и произвольных сообщений, авторизация диагностики, порядок событий, ротация и чтение архивов, доступ по ссылке, истечение/отзыв/замена ссылки, защита от чтения произвольных файлов и symlink, ограничение команд бота администратором, повтор команды и запрет выдачи ссылки при постороннем участнике. Отдельно проверены интерфейсы Web/Windows и панели администратора, сборка Android и согласованность версии APK. Физические телефоны и TURN пользователя из этой среды недоступны.
